# Start and Open 仕様

## この文書の役割

- SRSセクションのトグル挙動をどうするかの検討から派生した、汎用機能の仕様。
- 2026-07-07 の対話で方向が固まった。
- Status: Draft（`srs/start-and-open` ブランチで実装予定。仕様 → テスト → 実装の順で作る）。
- SRSの成長ロジックは [[SRS仕様]] を参照。この文書はノートを開く挙動だけを扱う。

## 何をするか

チェックボックスの開始操作（`- [ ]` → `- [/]`）と同時に、その行の `[[リンク]]` 先ノートを開く機能。

目的は、いつかやりたいこと（SRSで表面に出てくる someday 項目）を、開くという別の一手を挟まずに着手できるようにすること。開いて処理して初めて完了、という運用では、開始と「ノートを開く」を1操作にまとめることで、開くか後回しにするかを迷う離脱ポイントが消える。1枚あたりの差は小さくても、毎日繰り返す習慣が続くかどうかに効く。

## 有効化

- 設定に「Start and Open」トグルを1つ追加する。**既定は OFF。**
- OFF のときは現行のまま。開始しても何も開かない。
- モバイルとPCで別々の設定を持ちたい要件があるが、ユーザーが端末ごとに `.obsidian`（`data.json`）を分けて運用しているため、プラグイン側で `Platform.isMobile` の分岐は入れない。素の真偽値1つの設定にして、端末ごとに別々の値を持たせる。
- 想定する使い分け: モバイル OFF、PC ON。

## 起動条件（開くのはどの操作か）

- 対象は **開始操作（`- [ ]` → `- [/]`）のみ**。
- 具体的には次の経路：
  - Editor Checkbox Override の短押し `- [ ]` → `- [/]`
  - コマンド `toggle-task` / `start-task` の実行で開始になったとき（設定 ON のときのみ）
  - コマンド「Start and Open Note」の実行（設定に関わらず必ず開く）
- 開くタイミングは `handleToggleTask` 本体に置き、開始（未着手→実行中）になったら設定 `startAndOpenEnabled` に従って開く。`start-and-open-note` だけは `openOnStart: 'always'` で設定を無視して開く。チェックボックス経路も同じ判定で揃える。
- 以下では開かない：
  - 完了 `- [/]` → `- [x]`
  - 長押しの各遷移（前の時刻で開始、未着手へ戻す等）
  - `- [x]` → `- [ ]` などの戻し
- 設定「Start and Open」が OFF のときは、上記いずれでも開かない。
- Editor Checkbox Override が OFF のときは、チェックボックス経由では開かない（コマンドは常に使える）。

## 開始時刻

- 開始で `- [/]` にするとき、開始時刻 `HH:mm` は通常どおり打つ。SRSも同じ。
- `[/]` の作り方はルーチンと共通で、SRS専用の分岐は作らない。

## 開いたあとのカーソル（フォーカス）の既定

`openLinkText` の `OpenViewState.active` で制御する。

- **既定は `active: true`**。開いた先のノートに常にカーソルを移す。2026-07-08 の対話で「開いて → 作業して → もう一度 toggle で閉じて完了」というループ（次節）を導入したのに合わせ、SRS範囲かどうかで出し分けていた旧仕様をやめ、常にフォーカスに一本化した。
- カーソルが移ったノートは、次節の「開いた先で完了して閉じる」ループの対象になる。開いた先で toggle すると、開始元のデイリー行が完了し、そのタブが閉じてデイリーへ戻る。
- 開いた先ノートを読む必要がなくても一瞬そのノートに移る、という小さな引っかかりは受け入れる。操作数は変わらず（開始で1回、完了で1回）、タブは自動で閉じ、フォーカスはデイリーへ戻るため。仕様を1本にする単純さを取った。

旧仕様（SRSマーカー範囲内だけ `active: true`）は廃止した。`isLineInSrsRegion` は参考のため残すが、フォーカス判定には使わない。

## frontmatter による上書き

- 開くリンク先ノートの frontmatter に真偽値のキー `open_focus` があれば、既定（`true`）より優先して、カーソルを移すかどうかを決める。
- キーが未記載なら既定 `true`。
- `open_focus: false` を持つノートはカーソルを移さない（隣に開くだけ）。この場合そのノートはループ対象にならず、完了は従来どおりデイリーで行う。読むだけで開いた先で操作しないノートの逃げ道。
- 宣言は開かれる側のノートに乗る。そのノートが「自分はこう開かれたい」を持ち歩く形。

判定の優先順位（開くと決まったあと、カーソルを移すか）：

1. リンク先ノートの frontmatter に `open_focus` があればその値
2. なければ `true`（常にフォーカス）

## リンクの扱い

- 開く対象は、開始した**物理行**にある `[[wikilink]]`。
- リンクが無い行（`- [ ] 歯磨き` のような素のタスク）は、開く対象が無いので開始だけ行い、何も開かない（素通り）。
- リンクが複数ある行は、**先頭の `[[...]]`** を対象にする。

## 完了と、開いた先で閉じるループ

完了の経路は2つある。

- **デイリーで完了**: 従来どおり。デイリーノートのチェックボックス2度目の押下 `- [/]` → `- [x]`。`open_focus: false` のノート（カーソルを移さず隣に開いただけ）はこの経路で完了する。
- **開いた先で完了して閉じる（ループ）**: カーソルを移して開いたノートの中で `toggle-task` を押すと、開始元のデイリーの実行中行（そのノートを指す `- [/]`）が完了になり、開いていたタブが閉じてデイリーへフォーカスが戻る。

ループの流れ:

デイリーで toggle-task → 新タブでノートが開いてカーソルが移る → 作業 → もう一度 toggle-task → 開始元の行が完了、そのタブが閉じてデイリーに戻る。

ピン留めしたデイリー1枚＋開いては閉じる1枚で、タブは増えも減りもしない。

### ループの成立条件

- 開いた先ノートが、カーソルを移して開かれたもの（`active: true`）であること。開いた時点で「開いた先パス → 開始元デイリーパス」をプラグイン内のメモリに覚える。
- そのノートで toggle-task を押したとき、開始元デイリーがいずれかのタブで開いていて、そのノートを指す `- [/]` 行が残っていること。
- 上の対応が取れないとき（メモリに無い・開始元が閉じている・実行中行が見つからない）は、ループは走らず通常の toggle 動作にフォールバックする。デイリーノート以外での通常 toggle は「デイリーで使ってください」の警告になる。

### 行の特定

- 開始元の行は行番号ではなくリンク先で照合する。開始元デイリーの内容を走査し、実行中（`- [/]`）でその先頭リンクが今開いているファイルに解決される最初の行を対象にする。行がずれても壊れない。
- 完了処理は通常の完了パイプラインをそのまま流す（ドリフト補正・@done マーカー・SRS の repeat 成長を含む）。ノート内に別の完了ロジックは作らない。

### メモリの寿命

- 対応はメモリ上のみ。Obsidian を再起動すると消える。その場合は開き直せば復活する、という割り切り。ノート側に隠しマーカーは書き込まない。
- SRS対象ノートはこの完了で repeat が成長する（[[SRS仕様]] の完了時の動作）。

## コマンド

- 「Start and Open Note」コマンドを登録し、コマンドパレット / ホットキーからも同じ動作を呼べるようにする。
- 実装は開始＋開くの処理を共有関数に切り出し、コマンドとチェックボックスの両方がその関数を呼ぶ。
- チェックボックスが `executeCommandById` でコマンドをID実行する形にはしない（コマンド実行経路を二重に通ることになり壊れやすい）。

## 開かないケースまとめ

- 設定「Start and Open」が OFF
- Editor Checkbox Override が OFF（チェックボックス経由の場合）
- 開始（`- [ ]` → `- [/]`）以外の遷移
- 行に `[[リンク]]` が無い

## 境界・エッジケース

- SRSマーカー範囲内だが frontmatter に `open_focus: false` を持つノート → カーソルは移さない（frontmatter 優先）。
- SRSマーカー範囲外だが frontmatter に `open_focus: true` を持つノート → カーソルを移す。
- 既に `- [/]`（開始済み）の行で開始操作は発生しない（完了になる）ので、開く挙動も走らない。
- リンク先ノートが存在しない `[[未作成ノート]]` → Obsidian標準の新規作成挙動に従う（openLinkText の既定）。この場合のカーソル既定も同じルールで決める。
