## 何をするか

routine/ フォルダのノートと同じ YAML・同じ表示で動くが、完了するたびに repeat の間隔が自動で広がっていく仕組み。暗記カードのような細かい評価（hard / good / easy）はしない。チェックしたら伸びる、それだけ。

## incubate 構想からの変更点

incubate 構想では `@x` / `@hard` マーカーで「間隔を縮める」操作を想定していた。SRS ではそれをやらない。「明日もやりたい」と思ったら routine/ にノートを手で移動する。間隔の調整は仕組みではなく、フォルダ移動というアナログな判断で行う。

incubate 構想では growth rate をプラグイン設定で管理し、jitter や max interval も設定項目として想定していた。SRS の初期実装ではこれらは全部なし。growth rate は 2〜3 の乱数で固定。

incubate という名前は SRS に変わった。

## フォルダで分ける理由

routine-category のようなフィールドで区別する方法もあるが、フォルダで分ける。理由は「SRS すべきではない」という判断をノートの移動で表現したいから。routine/ に移動すれば SRS から外れて普通のルーチンになる。チェックボックスの完了処理に判断を組み込むのは難しいので、フォルダ移動というアナログな操作に任せる。

## 完了時の動作

srs/ フォルダにあるノートを完了すると：

1. 現在の repeat を取得する（未設定なら 1 として扱う。0 なら 1 として扱う）
2. next_due を today + 現在の repeat で更新する
3. repeat に 2〜3 の乱数をかけて、整数に丸める（repeat は常に整数）
4. repeat を新しい値で書き戻す

next_due の計算には成長前の repeat を使う。成長後の repeat は次回の完了時に使われる。

routine/ フォルダのノートは今まで通り。repeat は伸びない。

## 成長の感覚

growth rate は 2〜3 の乱数。repeat: 1 から始めた場合の推移（中央値での例）：

repeat: 1 から始めた場合（next_due は成長前の repeat で決まり、repeat は完了後に育つ）：

- 1回目完了: 1日後に出る。repeat が 2〜3 に育つ
- 2回目完了: 2〜3日後に出る。repeat が 4〜9 に育つ
- 3回目完了: 4〜9日後に出る。repeat が 8〜27 に育つ
- 4回目完了: 8〜27日後に出る。repeat が 16〜81 に育つ

4回チェックすれば週1〜月1以上の頻度まで開く。振り返りレベルの雑さで回す運用に合っている。

## YAML

routine と同じ YAML をそのまま使う。SRS 専用のフィールドは追加しない。

```yaml
---
repeat: 1
next_due: 2026-06-30
---
```

start, estimate, section, start_before, summary_role もそのまま使える。SRS 完了時にこれらのフィールドは触らない。

## routine/ に移動したとき

SRS/ のノートを routine/ に移動すると、repeat が成長済みの値（例: 20）のまま残る。routine 側では repeat: 20 は「20日ごと」として動くので、毎日やりたいなら手で repeat: 1 に直す必要がある。当面はこれを許容する。

## ノートの分類と整理

srs/ フォルダはフラットに使う。サブフォルダは作らない。

142件中117件が本の振り返りで残り25件がそれ以外だが、日次の運用ではその日 due のものだけ出てくるので、フォルダ内の見通しが問題になる場面は少ない。一覧が必要なときは Dataview（`_SRSタスク一覧.base` など）で作る。

将来、分類が必要になった場合はサブフォルダ（srs/本/ など）の方向で考えている。タグで分類する方法もあるが、「SRS をやめる」操作がタグを消すよりフォルダから出す方が直感的で、消し忘れも起きない。SRS 対象の判定をフォルダで行っている設計と一貫する。サブフォルダにする場合は `isSrsFile` を再帰走査に変えるコード変更が要る。確定ではないが、方向としてはサブフォルダ寄り。
