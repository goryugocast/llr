# 振り返りビュー

## 目的と入口

日中の操作用サイドバーとは別の中央タブで、日をまたいで活動と補足を読み、自分で日記を書く材料を得る。コマンド「振り返りを開く」と履歴アイコンから開く。元ノート・LLR記法・ルーチンを変更しない。LLM・外部送信・個人DBは使わない。

## 記録と時間帯

- Daily Notesの有効なフォルダ・日付形式で対象ノートを探す。日付の所属は元ノートを正とする。
- 標準では完了したチェック項目（`[x]`）だけを活動として扱う。未完了（`[ ]`）・実行中（`[/]`）は補足を含めて除外する。ノート冒頭の前書き・固定本文を活動や独立メモとして拾わない。チェック項目ではない記録・見出し以降の独立メモは保持し、完了記録は実績時刻なし・0分でも残す。補足本文内のネストしたチェックリストは本文として保持する。
- `<!-- llr:srs start -->` から `end` または `done` までのSRSエリアは、完了済みもメモも含めて除外する。同じノートへのリンクでもエリア外の完了記録は対象。コード例のマーカーは範囲として解釈しない。
- この除外を当面の標準とし、設定画面には項目を追加しない。将来の切り替えは検討可能だが、方式・設定UIは未決。対象判定は表示処理と分けて変更できるようにする。
- TaskParserの実績開始・終了だけを時間軸へ使用し、予定時刻を実績として補わない。
- 日界はLLRの3時。午前0〜2時台は翌朝として並べる。終了が開始より早ければ翌日へ進め、日跨ぎも切り捨てない。
- 1時間ごとに実績の重なりが最大の活動を代表にする。同点は元行順。同じ代表が続けばまとめる。個人カテゴリ、睡眠・外出優先は導入しない。
- 元記録は最も重なるブロックへ一度だけ所属する。同じ活動が離れた時間帯の代表にもなった場合、所属記録のない時間帯は展開のない概観として表示する。時刻なしは別のまとまりに残す。補足は元タスクの次の行から、次のタスク・見出しまでをインデントの有無によらず保持する。複数段落・URL・箇条書きも落とさず、タスクのない独立した本文もメモとして残す。絵文字からAI由来を推定しない。タイトル・補足はObsidianのMarkdown表示でリンク・別名・箇条書き・チェック項目を読める形にする。チェック項目は読み取り専用とし、振り返りから元ノートを書き換えない。コード中の記法はコードとして残す。

## 連続スクロールと位置

- 古い日から新しい日へ並べ、上端で過去、下端で今日までの新しい日を追加する。初回に全ノート本文を読まない。
- ノートのない期間は日数を示して省略する。日付ジャンプ先が存在しなければ空の日を表示する。今日へ戻れる。
- 追加・更新は表示中の元行または日付の画面内位置を基準に補正する。展開状態と別タブ復帰時の位置を維持する。実行中への自動追従はしない。
- 長い遡行では表示日数を制限して反対端を取り除く。戻れば再読込できる。表示は最大35日分に制限し、展開内容は開いたブロックのみ描画する。
- 詳細はブロックごとに個別に開閉する。一括操作は、日付・「今日へ」と同じ行に置くボタン1つで切り替える。すべて開いていれば「閉じる」、一部でも閉じていれば「開く」。一括操作であることはアクセシブル名で補う。専用の段や「詳細」ラベルは追加しない。操作領域はコンパクトにまとめ、本文やメモの読みやすい余白は保つ。
- 一括操作は表示中の全日と、その後スクロールで続く日にも適用する。個別に開閉した状態は更新・日付追加でも維持し、次の一括操作で揃える。閉じる際は、読んでいた補足の親活動を見失わないよう位置を補正する。
- 元記録から別の中央タブで元ノートの該当行へ移動できる。「元ノートへ」はアイコンで保持する。導線の引き続きの検討は、[UI改善Issue #9](https://github.com/goryugocast/llr/issues/9)で扱う。

## 表示設計

上部は左に「〈 年/月/日（曜）〉 今日」、右に「開く／閉じる」を置く。日付そのものを押すと標準カレンダーが開き、別の可視日付入力を並べない。左右は暦の前後1日へ移動し、無記録の日も飛ばさない。閲覧日付はスクロールへ追従する。今日では右矢印を無効にし、未来日は選択不可。「今日」は常設・有効のままとし、今日の先頭へ戻れる。矢印と文字ボタンの透明な通常状態・ホバーはLLRサイドバーと共有する。狭い幅では曜日だけを省略し、年と操作群を一行に保つ。非表示のネイティブ日付入力はレイアウトやTab移動へ重複参加させず、カレンダー操作中の選択値をスクロール追従で上書きしない。

時刻軸と活動の領域を分ける。軸は数字だけの2時間刻み（0・2・4…）とし、活動の開始位置と高さは1時間単位で計算する。ラベルのない13時なども座標は持つ。軸の数字を見出しへ重ねて表示せず、「:00」「翌」「○日後」は加えない。元記録の正確な開始・終了時刻は本文内で読む。

概観は03:00〜翌03:00の日別範囲へ収める。日跨ぎは概観だけ日界で区切り、元記録の全時刻・本文は変更せず一度だけ展開する。範囲の外で始まる記録は「このノートの日界後の記録」に残す。単独の0分・終了未記録も該当する1時間の概観へ含める。これは表示上の所属であり、元記録の実績区間を補わない。先頭末尾の空白時間は省略し、活動間の空白は時間軸の間隔として残す。

閉じた活動は1時間1マスの一定尺度とし、通常ノートの行高とテーマの余白から高さを算出する。デスクトップ最小32px・タッチ最小44pxを確保する。開いた活動の高さは、元の時間帯の高さと「見出し＋本文に必要な高さ」の大きい方とする。元の時間帯へ本文高を加算したり、本文の後ろへ残り時間分の空白を足したりしない。内部の時刻を帯の全高へ均等に配分し、後続活動は増加した高さだけ押し下げる。12〜15時なら13時は全高の1/3、14時は2/3の位置となる。開いている帯だけは読むために局所的な時間尺度が伸びる。個々のメモを実時刻の縦位置に置く方式ではない。

活動の占有範囲は軸の右側だけの薄い無彩色の面で示す。色はテーマのホバー色を薄くしたものを使い、分類色は導入しない。枠・影・追加の内外余白は付けず、開閉で基調色を変えない。括弧・継続罫・活動名の反復・実績の所要時間の重複表示は置かない。元lifelog画面の「軸で時刻、面で占有範囲を読む」構造を参考にし、本文高を最初の1マスの後へ一括で足す展開計算は移植しない。

角丸10px、ホバー色、120msの変化はLLRサイドバーと同じ変数を使う。閉じた活動は全時間帯を一つの操作対象とし、全体のホバー・フォーカスで操作面が強まり、どこを押しても活動全体が開く。開閉矢印は置かない。開始見出しはネイティブsummaryでキーボード操作と展開状態を保持する。開いた後は開始見出しだけが閉じる操作とホバーの対象で、本文・継続時刻・余白では閉じない。

元記録はタイトルと小さな移動アイコン、その下に控えめな開始・終了時刻、続いてメモを置く。開始と終了が同じなら時刻を一度だけ表示する。アイコンのツールチップとアクセシブル名は「元ノートへ」。見出し内リンクは文字表示とし、本文内のリンク・別名・Markdownは機能する。本文の文字選択とリンク操作を妨げず、チェック項目は読み取り専用。

本文は通常ノートと同じ `--font-text`・`--font-text-size`・`--line-height-normal` と通常の太さを使う。操作・時刻・日付はテーマのUI変数を使う。本文段落の余白を保ち、メモのない短い記録間の余白は小さくする。閲覧中の日付は固定操作領域に追従表示し、日付入力の操作中を除き同じ日付へ更新する。最終日は短い日でも上端へ移動できる高さを確保する。

### 実画面での受領基準

通常・ホバー・展開を同じ実データで比較する。3時間の活動内と次の活動の境界で目盛り位置が均等であること、1時間・長時間・無記録の範囲が区別できること、連続する日と午前0時の跨ぎを読めることを確認する。メモが操作ボタンより先に目に入り、展開中も所属日がわかり、本文が安全に読めることを確認する。

2026-11-05の第一版は、本人の元アプリ画像と展開の指摘をもとにAstraへ相談して実装し、通常ノート・LLRサイドバーと並んだ実画面を再レビューした。機能テストやAIの視覚評価は本人の最終受領の代替ではない。面の濃さや長文の局所拡大は引き続き実用時の判断対象とする。モバイル実機は未確認。

## 検証範囲

`npm test -- --run` は、メモ抽出・冒頭文除外・未完了/SRS除外・予定と実績の分離・日跨ぎ・元記録の一度だけの所属、展開中も帯内で均等な目盛り座標・2時間ラベル・日界内の概観と元記録の保持・時刻だけの記録による伸長防止、および追加読込/更新/タブ非表示時の位置保持を検証する。位置保持の単体テストは合成した画面寸法を使うため、ObsidianのMarkdown表示を検証したことにはしない。

配備したプラグインで振り返りタブを開き、`npm run test:reflection:obsidian` を実行すると、合成データをObsidianの描画処理に通す。別名リンク、複数段落と強調、コード内の記法、読み取り専用チェック項目、リンク移動の呼び出し、個別・一括開閉の併用とボタン表示、追加日の開閉状態、再描画後の展開維持、描画部品の解放、展開帯内から次の活動境界までの等間隔、余分な時間尾部の非加算、一括描画中の手動スクロール優先を検証する。ノートの作成・変更や実際のリンク先への移動は行わず、一時的な表示とテスト用の置き換えは終了時に戻す。対象は稼働中の配備版なので、実装変更後の確認では許可されたビルド・配備・リロードを先に行う。文字の重なりや読み心地は引き続き実画面で目視する。

合成fixtureで抽出・所属・境界条件・位置保持を検証し、型検査・lintを通す。明示許可のもとでビルド・Vault配備・リロードを実施し、デスクトップObsidianで中央タブの起動、過去日追加・補足展開・別タブ復帰時の位置保持とエラーなしを確認済み。画面のスクリーンショットを目視し、実ノート2日分の非インデント補足、印なしの複数行メモが欠けずに読めることも元ノートと照合済み。別名リンク・強調・ネストした読み取り専用チェック項目・コード内の記法は、Obsidian上の合成データでも検証した。クリックで既存ノートへ移動し、チェック操作で原文が変化しないことを確認。モバイル実機は未確認。

配備時はVault側のバージョン番号だけでなくコードも確認する。振り返り追加前に配備されていた0.4.2のセクション日界順序、日本語の「時」表記、プロパティチェックボックス保護を保持する。対応するソース・テストはorigin/mainのe758d39時点を反映している。
