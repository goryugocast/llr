# 振り返りビュー

## 目的と入口

日中の操作用サイドバーとは別の中央タブで、日をまたいで活動と補足を読み、自分で日記を書く材料を得る。コマンド「振り返りを開く」と履歴アイコンから開く。元ノート・LLR記法・ルーチンを変更しない。LLM・外部送信・個人DBは使わない。

## 記録と時間帯

- Daily Notesの有効なフォルダ・日付形式で対象ノートを探す。日付の所属は元ノートを正とする。
- 標準では完了したチェック項目（`[x]`）だけを活動として扱う。未完了（`[ ]`）・実行中（`[/]`）は補足を含めて除外する。ノート冒頭の前書き・固定本文を活動や独立メモとして拾わない。チェック項目ではない記録・見出し以降の独立メモは保持し、完了記録は実績時刻なし・0分でも残す。補足本文内のネストしたチェックリストは本文として保持する。
- `<!-- llr:srs start -->` から `end` または `done` までのSRSエリアは、完了済みもメモも含めて除外する。同じノートへのリンクでもエリア外の完了記録は対象。コード例のマーカーは範囲として解釈しない。
- この除外を当面の標準とし、設定画面には項目を追加しない。将来の切り替えは検討可能だが、方式・設定UIは未決。対象判定は表示処理と分けて変更できるようにする。
- TaskParserの実績開始・終了だけを時間軸へ使用し、予定時刻を実績として補わない。
- 日界はLLRの3時。午前0〜2時台は翌朝として並べる。終了が開始より早ければ翌日へ進め、日跨ぎも切り捨てない。
- 1時間ごとに実績の重なりが最大の活動を代表にする。同点は元行順。同じ代表が続けばまとめる。個人カテゴリ、睡眠・外出優先は導入しない。
- 元記録は最も重なるブロックへ一度だけ所属する。同じ活動が離れた時間帯の代表にもなった場合、所属記録のない時間帯は展開のない概観として表示する。時刻なしは別のまとまりに残す。補足は元タスクの次の行から、次のタスク・見出しまでをインデントの有無によらず保持する。複数段落・URL・箇条書きも落とさず、タスクのない独立した本文もメモとして残す。絵文字からAI由来を推定しない。タイトル・補足はObsidianのMarkdown表示でリンク・別名・箇条書き・チェック項目を読める形にする。チェック項目は読み取り専用とし、振り返りから元ノートを書き換えない。コード中の記法はコードとして残す。

## 連続スクロールと位置

- 古い日から新しい日へ並べ、上端で過去、下端で今日までの新しい日を追加する。初回に全ノート本文を読まない。
- ノートのない期間は日数を示して省略する。日付ジャンプ先が存在しなければ空の日を表示する。今日へ戻れる。
- 追加・更新は表示中の元行または日付の画面内位置を基準に補正する。展開状態と別タブ復帰時の位置を維持する。実行中への自動追従はしない。
- 長い遡行では表示日数を制限して反対端を取り除く。戻れば再読込できる。表示は最大35日分に制限し、展開内容は開いたブロックのみ描画する。
- 詳細はブロックごとに個別に開閉する。一括操作は、日付・「今日へ」と同じ行に置くボタン1つで切り替える。すべて開いていれば「全部閉じる」、一部でも閉じていれば「全部開く」。専用の段や「詳細」ラベルは追加しない。操作領域はコンパクトにまとめ、本文やメモの読みやすい余白は保つ。
- 一括操作は表示中の全日と、その後スクロールで続く日にも適用する。個別に開閉した状態は更新・日付追加でも維持し、次の一括操作で揃える。閉じる際は、読んでいた補足の親活動を見失わないよう位置を補正する。
- 元記録から別の中央タブで元ノートの該当行へ移動できる。「元ノートへ」はアイコンで保持する。導線の引き続きの検討は、[UI改善Issue #9](https://github.com/goryugocast/llr/issues/9)で扱う。

## 表示設計

複数日の活動とメモを読むため、時間帯の概観と本文を分ける。概観は03:00〜翌03:00の日別範囲へ収める。日跨ぎの活動は概観だけ日界で区切り、一意に特定できる元記録がある場合、その実績終了先を「翌10:00まで」等の注記で示す。元記録の全実績時刻・本文は変更せず、一度だけ展開する。範囲の外で始まる記録は「このノートの日界後の記録」に残し、同日の軸を延長しない。時刻表記はHH:mm、翌日分は「翌 HH:mm」。

短い活動帯はデスクトップ32px/h（モバイル48px/h）を基準とする。2時間を超える帯は高さの増分を1/8へ圧縮し、最大80px（モバイル120px）に抑える。長時間帯で代表と同名の実績記録が一意に特定できる場合だけ、「実績○時間」と実際の所要時間を添える。代表帯は時間単位に丸められるため、その長さを実績の所要時間として表示しない。活動の前後にある空白時間は省略し、活動間の空白は時刻範囲を示す1行にまとめる。本文を開くと後続の活動を押し下げ、本文の高さを経過時間として表さない。単独の0分・終了未記録は「時刻だけの記録」で時刻順に読む。

上部の重複する「振り返り」ラベルを閲覧中の日付に置き換え、スクロール先の日付へ追従させる。日付入力も操作中を除き同じ日付へ更新する。固定の操作領域を増やさず、メモ展開中も所属日を示す。

カード背景・太い枠・件数・全面の罫線は使わない。個別開閉は時刻・タイトル・開閉記号を含む見出し全体で行い、開閉記号はタイトル直前に置く。見出し内リンクは別名を含む文字表示とし、展開した元記録側のリンクは機能する。元ノート導線は各記録名の近くに置く小さな矢印アイコンとし、常時の文字ボタンを繰り返さない。ツールチップとアクセシブル名は「元ノートへ」とする。

本文の段落と行間は保ち、メモのない短い記録同士の間隔を小さくする。メモ付き記録との境目には余白を残す。対象判定、複数日の連続読込、個別と全体の開閉状態、閲覧位置保持は従来の契約を維持する。

### 実画面での受領基準

2026-11-05の独立した2名のレビューでは、時間軸の巨大な空白と日付境界での時刻の重複、日付の見失いやすさ、元ノートボタンの反復、開閉記号が右端だけにあることが問題となった。上記の変更はこの指摘への改善であり、本人の最終受領とは扱わない。

連続する3日を読んで空の時刻だけで画面を送らされないこと、展開中も所属日がわかること、メモが操作ボタンより先に目に入ること、タイトル付近で開閉状態と操作先がわかることを実際のObsidianで確認する。機能テストの合格だけでは表示設計を受領しない。実画面の再レビューで残る問題を判断する。

改善後の閉じた11月4日は約1,055pxから647pxとなり、次の日も同一画面に入る。再レビューで挙がった実績と代表帯の時間数の混同、開閉記号と線の重なり、元ノートアイコンの反復背景も修正し、最終の実画面レビューでは今回の修正範囲に即時修正を要する問題なしとのAI評価を得た。最終日は短い日でも上端へ移動できるよう閲覧領域の高さを確保する。本人の最終受領とモバイル実機の確認は別とする。

## 検証範囲

`npm test -- --run` は、メモ抽出・冒頭文除外・未完了/SRS除外・予定と実績の分離・日跨ぎ・元記録の一度だけの所属、長時間帯の圧縮・日界内の概観と元記録の保持・時刻だけの記録による伸長防止、および追加読込/更新/タブ非表示時の位置保持を検証する。位置保持の単体テストは合成した画面寸法を使うため、ObsidianのMarkdown表示を検証したことにはしない。

配備したプラグインで振り返りタブを開き、`npm run test:reflection:obsidian` を実行すると、合成データをObsidianの描画処理に通す。別名リンク、複数段落と強調、コード内の記法、読み取り専用チェック項目、リンク移動の呼び出し、個別・一括開閉の併用とボタン表示、追加日の開閉状態、再描画後の展開維持、描画部品の解放、一括描画中の手動スクロール優先を検証する。ノートの作成・変更や実際のリンク先への移動は行わず、一時的な表示とテスト用の置き換えは終了時に戻す。対象は稼働中の配備版なので、実装変更後の確認では許可されたビルド・配備・リロードを先に行う。文字の重なりや読み心地は引き続き実画面で目視する。

合成fixtureで抽出・所属・境界条件・位置保持を検証し、型検査・lintを通す。明示許可のもとでビルド・Vault配備・リロードを実施し、デスクトップObsidianで中央タブの起動、過去日追加・補足展開・別タブ復帰時の位置保持とエラーなしを確認済み。画面のスクリーンショットを目視し、実ノート2日分の非インデント補足、印なしの複数行メモが欠けずに読めることも元ノートと照合済み。別名リンク・強調・ネストした読み取り専用チェック項目・コード内の記法は、Obsidian上の合成データでも検証した。クリックで既存ノートへ移動し、チェック操作で原文が変化しないことを確認。モバイル実機は未確認。

配備時はVault側のバージョン番号だけでなくコードも確認する。振り返り追加前に配備されていた0.4.2のセクション日界順序、日本語の「時」表記、プロパティチェックボックス保護を保持する。対応するソース・テストはorigin/mainのe758d39時点を反映している。
