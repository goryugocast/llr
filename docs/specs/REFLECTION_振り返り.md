# 振り返りビュー

## 目的と入口

一つのLLR画面で、既存のタスク表示と、日をまたいで活動と補足を読むタイムラインを切り替える。タスク表示は既存の対象データ・Estimate・ノートを開く操作・タスク操作を保ち、メモを表示しない。時計アイコンでタイムライン、リストアイコンでタスクへ戻る。既存の「振り返りを開く」コマンドも同じLLR画面のタイムラインを開く。独立した履歴リボンは置かない。元ノート・LLR記法・ルーチンを変更しない。LLM・外部送信・個人DBは使わない。

## 記録と時間帯

- Daily Notesの有効なフォルダ・日付形式で対象ノートを探す。日付の所属は元ノートを正とする。
- 標準では完了したチェック項目（`[x]`）だけを活動として扱う。未完了（`[ ]`）・実行中（`[/]`）は補足を含めて除外する。ノート冒頭の前書き・固定本文を活動や独立メモとして拾わない。チェック項目ではない記録・見出し以降の独立メモは保持し、完了記録は実績時刻なし・0分でも残す。補足本文内のネストしたチェックリストは本文として保持する。
- `<!-- llr:srs start -->` から `end` または `done` までのSRSエリアは、完了済みもメモも含めて除外する。同じノートへのリンクでもエリア外の完了記録は対象。コード例のマーカーは範囲として解釈しない。
- この除外を当面の標準とし、設定画面には項目を追加しない。将来の切り替えは検討可能だが、方式・設定UIは未決。対象判定は表示処理と分けて変更できるようにする。
- TaskParserの実績開始・終了だけを時間軸へ使用し、予定時刻を実績として補わない。
- 日界はLLRの3時。午前0〜2時台は翌朝として並べる。終了が開始より早ければ翌日へ進め、日跨ぎも切り捨てない。
- 1時間ごとに実績の重なりが最大の活動を代表にする。同点は元行順。同じ代表が続けばまとめる。個人カテゴリ、睡眠・外出優先は導入しない。
- 元記録は最も重なるブロックへ一度だけ所属する。同じ活動が離れた時間帯の代表にもなった場合、所属記録のない時間帯は展開のない概観として表示する。時刻なしは解析データに保持するが、専用の見出しと記録枠（`.llr-reflection-untimed`）は表示しない。補足は元タスクの次の行から、次のタスク・見出しまでをインデントの有無によらず保持する。複数段落・URL・箇条書きも落とさず、タスクのない独立した本文もメモとして残す。絵文字からAI由来を推定しない。タイトル・補足はObsidianのMarkdown表示でリンク・別名・箇条書き・チェック項目を読める形にする。チェック項目は読み取り専用とし、振り返りから元ノートを書き換えない。コード中の記法はコードとして残す。

## 連続スクロールと位置

- 古い日から新しい日へ並べ、上端で過去、下端で今日までの新しい日を追加する。初回に全ノート本文を読まない。
- ノートのない期間は日数を示して省略する。日付ジャンプ先が存在しなければ空の日を表示する。今日へ戻れる。
- 追加・更新は表示中の元行または日付の画面内位置を基準に補正する。展開状態と別タブ復帰時の位置を維持する。実行中への自動追従はしない。
- 長い遡行では表示日数を制限して反対端を取り除く。戻れば再読込できる。表示は最大35日分に制限し、展開内容は開いたブロックのみ描画する。
- 詳細はブロックごとに個別に開閉する。一括操作は、日付・「今日」と同じ行に置くボタン1つで切り替える。Backlinksと同じ上下矢印（move-vertical）を使い、すべて開いていれば「すべて折りたたむ」、一部でも閉じていれば「すべて展開」をツールチップとアクセシブル名で示す。専用の段や「詳細」ラベルは追加しない。操作領域はコンパクトにまとめ、本文やメモの読みやすい余白は保つ。
- 一括操作は表示中の全日と、その後スクロールで続く日にも適用する。個別に開閉した状態は更新・日付追加でも維持し、次の一括操作で揃える。閉じる際は、読んでいた補足の親活動を見失わないよう位置を補正する。
- 各記録には元デイリーノートへの移動アイコンを置かない。本文内のノートリンクはそのまま利用できる。

## 表示設計

スクロール領域に独自の説明ラベルは付けない。

上部はLLRサイドバーと同じ「MM-DD 曜」の日付表示と、その右に「〈 TODAY 〉」を置く。日付を押すと標準HTML日付入力のカレンダーを開き、選択した日のタイムラインへ移動する。ノートのない日も選択でき、ノートは作成しない。独立したカレンダーアイコンは置かない。右端は一括開閉・用紙アイコン・表示切替の順とし、タスク表示では一括操作とその空枠を取り除く。表示を切り替えても日付と移動操作は左、利用可能な操作は右のまとまりを保つ。各記録の移動矢印も表示しない。左右は暦の前後1日へ移動し、無記録の日も飛ばさない。閲覧日付はスクロールへ追従する。今日では右矢印を無効にし、未来日は選択不可。「今日」は常設・有効のままとし、今日の先頭へ戻れる。矢印と文字ボタンの透明な通常状態・ホバーはLLRサイドバーと共有する。日付と他の操作は高さと文字の中心を揃える。狭幅は採用寸法に従って操作幅と日付文字を調整し、本文文字を縮めない。前年以前では年を日付の上に小さく補う。非表示のネイティブ日付入力はレイアウトやTab移動へ重複参加させず、カレンダー操作中の選択値をスクロール追従で上書きしない。

時刻軸と活動の領域を分ける。軸は数字だけの2時間刻み（0・2・4…）とし、活動の開始位置と高さは1時間単位で計算する。ラベルのない13時なども座標は持つ。軸の数字を見出しへ重ねて表示せず、「:00」「翌」「○日後」は加えない。元記録の正確な開始・終了時刻は本文内で読む。

概観は03:00〜翌03:00の日別範囲へ収める。日跨ぎは概観だけ日界で区切り、元記録の全時刻・本文は変更せず一度だけ展開する。範囲の外で始まる記録は「このノートの日界後の記録」に残す。単独の0分・終了未記録も該当する1時間の概観へ含める。これは表示上の所属であり、元記録の実績区間を補わない。先頭末尾の空白時間は省略し、活動間の空白は時間軸の間隔として残す。

閉じた活動は1時間1マスの一定尺度とし、通常ノートの行高とテーマの余白から高さを算出する。デスクトップ最小40px・タッチ最小44pxを確保する。開いた活動の高さは、元の時間帯の高さと「見出し＋本文に必要な高さ」の大きい方とする。元の時間帯へ本文高を加算したり、本文の後ろへ残り時間分の空白を足したりしない。内部の時刻を帯の全高へ均等に配分し、後続活動は増加した高さだけ押し下げる。12〜15時なら13時は全高の1/3、14時は2/3の位置となる。開いている帯だけは読むために局所的な時間尺度が伸びる。個々のメモを実時刻の縦位置に置く方式ではない。

活動の占有範囲は軸の右側だけの薄い無彩色の面で示す。色はテーマのホバー色を薄くしたものを使い、分類色は導入しない。枠・影・追加の内外余白は付けず、開閉で基調色を変えない。括弧・継続罫・活動名の反復・実績の所要時間の重複表示は置かない。元lifelog画面の「軸で時刻、面で占有範囲を読む」構造を参考にし、本文高を最初の1マスの後へ一括で足す展開計算は移植しない。

角丸10px、ホバー色、120msの変化はLLRサイドバーと同じ変数を使う。閉じた活動は全時間帯を一つの操作対象とし、全体のホバー・フォーカスで操作面が強まり、題名リンク以外の面を押すと活動全体が開く。見出し右端に閉状態は右向き、開状態は下向きの矢印を置く。開始見出しはネイティブsummaryでキーボード操作と展開状態を保持する。開いた後は開始見出しの題名リンク以外だけが閉じる操作とホバーの対象で、本文・継続時刻・余白では閉じない。

元記録はタイトル、その下に控えめな開始・終了時刻、続いてメモを置く。開始と終了が同じなら時刻を一度だけ表示する。題名の元データにあるノートリンクは、閉状態・展開状態とも通常の紫色と常時下線で表示し、押すとリンク先へ移動する。リンク操作は開閉に伝播させない。リンクのない題名に架空のリンクを付けず、複数リンクも個別に保つ。同じ代表題名は展開本文へ重複させない。本文内のリンク・別名・Markdownも機能する。本文の文字選択とリンク操作を妨げず、チェック項目は読み取り専用。

背景・文字・ホバーはObsidianテーマの `--background-primary`・`--text-normal`・共有のホバー変数を使い、親ペインの背景色に依存させない。ライト・ダーク双方で配色を確認する。活動名15px・行高1.5、補足12pxにそろえ、フォントはObsidianのテーマ変数を使う。固定操作部は左右20px。時間軸には24pxの数字専用領域と活動面まで8pxの空きを確保し、活動面の左端を32px、題名・展開本文を40pxに置く。数字を活動面・境界線と重ねず、桁全体を専用領域内に収める。タイトルは一行、展開本文は折り返しを維持する。時間の高さは本文行高とテーマ余白から算出し、40px以上、タッチ環境44px以上で活動・空き時間へ同じ尺度を適用する。幅変更時も再描画を待たずに反映する。操作・時刻・日付はテーマのUI変数を使う。本文段落の余白を保ち、メモのない短い記録間の余白は小さくする。閲覧中の日付は固定操作領域に追従表示し、日付入力の操作中を除き同じ日付へ更新する。最終日は短い日でも上端へ移動できる高さを確保する。

### 表示の判断基準

均等な時間軸から、いつ何をしていたかを大まかに把握できることを優先する。既存LLRサイドバーに寄せる対象は配色・文字・余白・ホバー等の見え方であり、時間軸をなくした記録一覧への変更ではない。比較用に追加した一覧は本人に不採用と判断され、切替ごと撤去した。分単位の実績時刻や「○時台」のラベルを概観へ増やして、位置・面積で読める時間情報を文字に置き換えない。細かな情報を確認するためだけの開閉を増やさない。

### 一つのLLR画面での切替

既存の `llr-summary-view` を一つのLLR画面として使い、タスクとタイムラインの描画・操作・対象データは分けて保持する。切替は日付行右端の単一ボタンで、ツールチップとアクセシブル名は「タイムラインを表示」「タスクを表示」。新しいタブ行や操作行は増やさない。タイムライン側にはEstimateを追加しない（採否は未決）。タスク側のEstimateは維持する。

同じ日を往復したときは各表示のスクロールとタイムラインの開閉状態を保ち、切替後は同じ場所の切替ボタンへフォーカスを移す。これは同じ画面を開いている間の状態保持で、再起動後のスクロールや個別展開の永続保存ではない。ワークスペースには表示モードと日付を保存する。表示日を変更してから切り替えた場合は、切替先もその日へ移動する。別日へ移ったタスク表示は先頭から始める。タイムラインの日付移動は初回読込・追加読込・更新と同じキューで直列実行する。ワークスペース復元時にペインが非表示、またはプラグインCSSが未適用なら指定日を保持し、スクロール可能な描画領域になってから位置を合わせる。最終日にも移動できる高さを位置計算前に確保し、前日の位置へ制限されることを防ぐ。読み込みに失敗した切替は直前の表示へ戻し、再試行できるようにする。タスクとタイムラインの上部日付は表示日の選択だけを行い、ノート操作は別の用紙アイコンが担当する。タイムラインの一括操作は展開対象なしでは無効にする。

旧振り返りタブの保存状態は新しいLLR画面へ移行し、同じサイドバー内の重複を一つにまとめる。中央ペインに置いた独立したLLR画面は残す。埋め込んだ描画用ItemViewの空コンテナやネイティブ余白で、本文の幅・高さを二重に消費しない。

採用した構造・画像・未決事項は[Spaceの最新デザイン資料](https://chatgpt.com/space/page_704406bd107881918d09a479e1fd1c77)を参照する。元のCodexスレッドは `01a1aa5e-479c-7a72-9a33-0957e4ad5062`。広い画面での直接編集・開始停止・二列連動表示は今回の範囲に含めない。

### 実画面での受領基準

通常・ホバー・展開を同じ実データで比較する。3時間の活動内と次の活動の境界で目盛り位置が均等であること、1時間・長時間・無記録の範囲が区別できること、連続する日と午前0時の跨ぎを読めることを確認する。メモが操作ボタンより先に目に入り、展開中も所属日がわかり、本文が安全に読めることを確認する。

2026-11-05の第一版は、本人の元アプリ画像と展開の指摘をもとにAstraへ相談して実装し、通常ノート・LLRサイドバーと並んだ実画面を再レビューした。機能テストやAIの視覚評価は本人の最終受領の代替ではない。面の濃さや長文の局所拡大は引き続き実用時の判断対象とする。モバイル実機は未確認。

### サイドバーの日付操作の検討案（未実装）

カレンダーの新規実装は現段階では進めず、振り返りの読みやすさ改善を先に扱う。

モバイルでは日付から今日のデイリーノートを作成する操作が頻繁に使われているため、現行の日付クリック操作を維持する（今日ならノートを開く・作成する。今日以外の未作成日は通知する）。将来案は「日付を押すとカレンダーを開き、選択日のノートを開く・なければ作成」。カレンダー上でノートの存在有無が分かること、同じ今日の日付を選び直した場合も作成できることが必要。振り返りのカレンダーとは選択後の役割を分ける。現在使うHTMLの `input[type=date]` / `showPicker()` はブラウザ標準で、Obsidian専用カレンダーではない。日ごとのノート存在マーカーを付けるAPIはないため、存在有無を表示できる別のカレンダーUIと、選択日の取得・作成処理が必要になる。参考：[MDN showPicker](https://developer.mozilla.org/en-US/docs/Web/API/HTMLInputElement/showPicker)、[date input](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/input/date)。この案は採用・実装未決。

- Obsidian標準の「今日のデイリーノートを開く」は未作成なら作る。実行中アプリでもcommand ID `daily-notes` を確認した（今回は実行・作成していない）。標準のフォルダ・日付形式・テンプレートに従わせる今日の導線として利用候補になる。[標準機能](https://help.obsidian.md/plugins/daily-notes)。LLRの現Todayは表示日の移動のみ。Todayを「今日を開く・作成する」操作に変えることも可能だが、画面移動の有無を含めて未決。

## 検証範囲
