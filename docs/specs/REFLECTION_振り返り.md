# 振り返りビュー

## 目的と入口

一つのLLR画面で、既存のタスク表示と、日をまたいで活動と補足を読むタイムラインを切り替える。タスク表示は既存の対象データ・Estimate・ノートを開く操作・タスク操作を保ち、メモを表示しない。時計アイコンでタイムライン、リストアイコンでタスクへ戻る。既存の「振り返りを開く」コマンドも同じLLR画面のタイムラインを開く。独立した履歴リボンは置かない。元ノート・LLR記法・ルーチンを変更しない。LLM・外部送信・個人DBは使わない。

## 記録と時間帯

### 今日の予定候補（実験ブランチ）

#### 崩れた入力の扱い（実装済み・未決）

この節は実装済みの条件と未決の判断を分けた仕様。「本人方針」は本人の示した方向、「AI案」「未決」は未採用の条件を表す。実装済みの範囲は次のとおり。

- 現在の時間枠で複数実行中の代表を切り替え、後続の完了後も古い止め忘れへ戻らない。過去の重複時間帯、完了実績と実行中との優先関係は変更しない。
- 無効な時計時刻を区間計算から外し、元の時刻文字列を展開内に残す。時刻を欠く完了・実行中の記録も時刻なしのまとまりで読めるようにする。
- 通常の逆転時刻は翌日補正後12時間以内なら日跨ぎ、それを超えれば開始位置の0分として並べる。本人が境界判断をAIへ委任したため、日中の時計範囲ではなく区間の長さで保護するAI判断として採用。原文は書き換えない。
- `summary_role: sleep` は12時間の推定上限から除外し、13時間の睡眠を保持する。過去の日付にも睡眠判定を渡す。睡眠のほぼ24時間の逆転は未決なので従来の計算を維持する。
- 巨大な見積もりから時間枠を無制限に生成しない。解析時の時間枠走査は日界から48時間までに制限し、元の見積もり値は変更しない。既存の日単位の表示範囲と正当な翌朝の記録を維持する。

##### 共通の表示原則

- ノートは正規化済みデータベースではない。複数実行中、重複、途中の編集を前提にする。表示側の判断でチェック状態、開始・終了時刻、見積もり、元行順を修正しない。
- 計算に使えない値と、表示から消してよい記録を同一視しない。対象記録は、代表・同じ所属の展開内・時刻不明のまとまりのいずれかで読めるようにする。元の時刻文字列、メモ、リンク、完了状態を保持する。
- 1時間の縦幅を一定にし、重複した区間を足して時間軸を伸ばさない。区間が不確定な記録を長い実績帯や未来予定にしない。0分扱いの区間を1時間の実績として計上しない。
- 壊れた1件のために日全体を表示不能にしたり、他の正常な実績・候補の所属を変えたりしない。座標・高さは有限かつ非負に保つ。

##### 複数実行中と止め忘れ

開始時刻の有効な実行中項目を、日界で正規化した開始順に比較する。「現在の枠でどれを代表に見せるか」の規則として実装し、実際の並行作業か止め忘れかは断定しない。代表以外の実行中も展開内などで読めるようにする。

| 入力例・観測時点 | 表示上の代表 | 判断の状態 |
|---|---|---|
| Aが10:00開始、Bが10:30開始、現在10:45。両方が実行中 | A。開始の古い方を優先 | 本人方針 |
| Aが10:00開始、Bが11:00開始、現在11:10。両方が実行中 | B。開始が1時間以上離れた新しい行動を優先 | 本人方針。「以上」なのでちょうど60分を含む |
| Aが10:00開始、Bが10:59開始、現在11:10 | A。開始差59分では切り替えない | 上記方針から導く境界例 |
| Aが10:00開始、Bが11:10開始、現在11:20 | B。Aは表示上の代表から外れるが、実行中の原文はそのまま残る | 本人方針 |
| Aが10:00開始のまま、現在12:00。他の実行中はない | A。経過が1時間を超えたという理由だけでは消さない | AI案。開始差と単なる経過時間を分ける |
| AとBがともに10:00開始 | 元ノートで上の行 | AI案。同時刻の安定した同点処理 |
| Aが23:40開始、Bが00:50開始、現在01:00 | 同じ論理日なら開始差70分としてB | AI案。時計表示の数値順ではなく日跨ぎを正規化 |
| Aが10:00、Bが10:40、Cが11:20開始、現在11:30 | C。現在代表Aとの差80分で切り替える | 本人採用。隣接する開始差だけでは判定しない |
| Aが10:00、Bが11:10、Cが11:20開始 | Bへ切り替えた後、Cとの差10分なのでB | 採用した代表基準の規則から導く例。単なる最新開始優先ではない |
| Bを代表にした後Bが完了し、古いAだけ実行中のまま残った | Aには戻さない。Bは完了実績に移り、古いAは止め忘れ候補として詳細に残す | 本人採用。Aを自動停止せず、終了時刻も補完しない |

Cへの切り替え後にCが完了した場合も、古いA・Bへ現在の代表を戻さない。時刻が進んだだけのAを消す規則とは別で、後続の開始で代表交代したことが条件。再描画・再読込でも古い項目が復活しないことをテストする。古い項目の存在を消すのではなく、現在の代表から外す。

まだ決める必要があること：この代表規則を現在の1時間枠だけに使うか、過去の重複時間帯にも適用するか。完成済み実績と実行中が現在枠で競合した場合の優先度も、この複数実行中規則と混同しない。元の実行中区間を新しい開始時刻で勝手に切らない。

##### 時計時刻の逆転・欠落・誤入力

| 入力例 | 表示と計算の扱い | 判断の状態 |
|---|---|---|
| 完了 `14:22 - 14:21` | 日中の誤入力とみなし、計算上は14:22の0分記録として並べる。展開内には原文の両時刻を残す。翌日扱いの23時間59分にはしない | 本人方針 |
| 完了 `14:22 - 14:22` | 正当な0分記録。14:22に所属し、両時刻を確認できる | 既存の0分保持を継続 |
| 完了 `23:50 - 00:10` | 正当な日跨ぎなら20分。0分に潰さない | 既存の日跨ぎ保持を継続 |
| 完了 `00:20 - 00:10`、または `02:59 - 02:58` | 夜間の短い逆転から翌日を推定しない案。表示計算上は開始位置の0分とし、原文を保持 | AI案。次の判定案を参照 |
| 完了 `22:00 - 21:59` | ほぼ24時間の帯へ自動変換せず、開始位置の0分とする案 | AI案。日中逆転と同じ表示上の扱い |
| `14:22 - 14:222`、`144:22 - 14:30` | 桁違いを勝手に削って補正しない。不正な区間を代表選択や長さの計算に使わず、原文の記録を残す | AI案 |
| `14:60`、`99:99`、`-1:30`、`:22`、`14:`、数字の代わりに文字 | 無効な時計値として扱い、別の正常時刻へ丸めない。`144:22`の末尾だけを拾って`44:22`などと解釈しない | AI案 |
| 開始だけ正しく、終了が欠落・不正 | **未決**。完了なら有効な開始位置に長さのない記録を置く案。実行中で終了がないのは正常なので開始から現在まで | 状態を区別する必要がある |
| 終了だけ正しい、または両側とも時刻なし | 時刻不明のまとまりで原文を読めるようにする。終了を開始へ転用しない | AI案 |
| 実行中の開始が15:00、現在14:00 | 未来の実績帯や負の長さを作らない。開始時刻の疑義として原文を残す。前日開始だと勝手に補完しない | AI案。現在の代表選びから外すかは未決 |
| 完了なのに終了が現在より未来、実行中なのに終了も記載済み | **未決**。チェック状態と時刻が矛盾しても原文を維持し、状態を自動変換しない | 時刻不確定として帯を作らない案 |

実装した日跨ぎの判定：まず両側の時計値が正常か確認する。終了が開始以降なら通常の差、同時刻なら0分。終了が開始より前の場合だけ、翌日補正した長さを計算する。通常タスクの翌日推定上限は12時間とする（本人から境界判断を任されたAI判断）。逆転時だけに使い、順方向の長時間記録の上限にはしない。睡眠の長時間例外も実装済み。原文は補正しない。

**睡眠の例外（実装済み）：** リンク先ルーチンに `summary_role: sleep` がある場合、通常タスク用の12時間等の推定上限から除外する。`20:00 - 09:00` は13時間の睡眠として保持する。タイトルや見積もり値だけで睡眠と推定せず、今日だけでなく過去の睡眠記録にも同じ判定を適用する。表示の縮尺・記録の展開・元時刻の保持は通常の実績と共通。既存の睡眠特例の入口は[Frontmatter仕様のsummary_role](ルーチンノートFrontmatter仕様.md#7-summary_role睡眠の特別扱い)。

| 入力 | 翌日補正した場合の長さ | 通常の逆転は12時間上限・睡眠は例外 |
|---|---|---|
| `23:50 - 00:10` | 20分 | 正常な日跨ぎ20分 |
| `22:00 - 06:00` | 8時間 | 正常な日跨ぎ8時間。03:00を越えても日跨ぎを認める |
| `18:00 - 06:00` | 12時間 | 境界を含め正常な日跨ぎ12時間 |
| `00:20 - 00:10` | 23時間50分 | 0分表示、原文の両時刻を残す |
| `02:59 - 02:58` | 23時間59分 | 0分表示、原文の両時刻を残す |
| `03:10 - 02:50` | 23時間40分 | 0分表示。日界をまたぐ形だけで翌日と推定しない |
| `14:22 - 14:21` | 23時間59分 | 本人方針どおり0分表示 |
| `02:30 - 03:30` | 通常の差で1時間 | 正常な1時間。日界の03:00を越えることと時計の逆転を混同しない |
| `20:00 - 09:00` | 13時間 | `summary_role: sleep`なら正常な13時間として保持（本人採用）。通常タスクにはそのまま例外を広げない |

12時間は逆転から翌日を推定する表示保護の境界で、正しい実績が12時間までという制限ではない。睡眠でもほぼ24時間になる小さな逆転をどう判定するかは未決。睡眠例外でも `14:222` や `144:22` の無効値を救済しない。見積もりとの不一致だけで正常な実績を誤入力扱いにしない。

03:00の日界は日付所属・並び順のために使い、日跨ぎを認める終了時刻を03:00未満に限定するためには使わない。そうすると`22:00→06:00`の正常な睡眠を壊す。ルーチンの拡張セクション値`2400`と、時計記録の`24:00`の有効性は別に扱う。時刻入力で現在許される`HHmm`などの省略形も、不正入力と一律には扱わない。

##### 見積もり・セクション・行構造

| パターン | 表示の仕様案／未決点 |
|---|---|
| 見積もり未指定、明示的な0分 | ともに比較上0分として候補を残す。0分を負数や非数値と混同しない |
| 負の見積もり、`NaN`、`Infinity`、非数値、型違い | 高さ・優先度・終了予定の計算に使わず、値と項目を残す。AI案は見積もり不明として0分候補と同じ補充対象にする |
| 極端な見積もり（例：10億分） | 入力値に比例して時間枠・目盛り・DOMを生成しない。元の数値は保持する。表示計算の上限値と見積もり不明へ落とす閾値は未決。480分の睡眠など通常の長時間記録は壊さない |
| 設定セクションの無効な時刻、型違い、空ラベル、重複ラベル、同じ境界時刻 | 日全体の描画を止めず、所属が確定しない項目は時刻不明として保持する。重複設定でどちらを採用するかは未決 |
| ノート見出しと設定・ルーチンのsectionが食い違う | 無関係な帯へ混ぜない。単一の有効なルーチンsectionを今日の未着手の所属元として優先する。複数・無効・欠落なら元の見出しを使う |
| 同じタイトル・同じリンクの複数行 | 元の各行を別の記録として保持する。タイトル一致で削除しない。1行を表示処理の都合で二重に割り当てることは防ぐ |
| 既存対象の空タイトル、リンク切れ、壊れたチェック記号、補足の途中編集 | 他の行を巻き込まない。チェック状態や所属が読めない行まで新たにタスクと認定するかは未決。通常の本文として読める経路を失わない |
| コード例中の時刻・チェック項目・見出し、SRS範囲 | 通常の活動やセクション設定と混同しない。入力が崩れても既存の対象範囲の除外を維持する |

##### 実装前に用意するテストの受領条件

1. 上記の本人方針と、決まった境界例を入力→代表・所属・原文表示の期待値にする。未決条件をテストで勝手に既成事実にしない。
2. 59分／60分／61分の開始差、同時刻、3件以上、深夜跨ぎ、新しい代表の完了後を組み合わせる。日中の逆転、深夜の正当な区間と疑わしい逆転を分ける。
3. 正常な一日に壊れた1件を挿入し、例外で日全体が消えない、正常な他項目の代表・所属が変わらない、対象行の欠落・重複がないことを確認する。同じタイトルの別行が残ることも確認する。
4. 原文・チェック状態・メモ・リンクを保存し、元ノートを書き換えない。壊れた時計文字列の一部だけを正常時刻として拾わない。
5. 座標・高さ・目盛り数が有限かつ範囲内、負や`NaN`がない、1時間の縮尺が一定、巨大値でも処理量が暴走しないことを確認する。画面が落ちないだけでなく、時刻やメモを展開して読める実表示も確認する。
6. 従来の一日分の正常例、0分記録、単独完了記録の時刻展開、予定だけの空展開省略を回帰確認する。異常系への対応で正当な日跨ぎや睡眠を消さない。

#### startとsectionの意図を生かす表示方針

今日の未着手予定に適用する。過去日の記録・完了・実行中は実績時刻で扱う。

- `start` は余裕を含めて着手を意識する時刻、`section` はその行動の所属時間帯。代表の置き場所を `start` の時刻だけから決めない。
- `start: 1750 / section: 1800` の晩ごはんは18時の行動、`start: 2045 / section: 2100` の促しは21時の行動として見渡せるようにする。短いリマインドを見積もりの長い候補との単純比較だけで展開内に隠さない。
- 明示された開始予定時刻は、代表を18時・21時の枠に置いた場合も17:50・20:45のまま読めるようにする。枠の時刻を実際の開始予定と誤読させない。推定した候補に架空の開始時刻を付けない。
- 完了したら予定候補から外し、実際に記録された開始・終了時刻で実績へ移す。15分の促しが終わった後も21時の予定枠を占め続けない。実績の高さと代表選択は既存の時間軸の規則に従う。
- 元の並び順をさらに生かす一般的な候補配置は未決。今回の変更では、時刻指定のない候補の見積もり比較・同点時の元順を維持する。
- 1時間あたりの縦幅は一定に保つ。この方針の採用は枠の高さの変更を意味しない。19時の家族会議のような強い時刻指定と、所属セクションの先頭候補が競合した場合の一般的な優先規則は、まだこの2例だけで確定しない。

今日の表示時にリンク先ルーチンの `section` を読み、設定されたセクション開始以上かつ行の開始予定以上の時刻を表示基準にする。単一の有効な数値sectionに限り、古いデイリーノート見出しより優先する。複数sectionは個々の展開先を一意に識別できないため、従来の見出し・開始予定で扱う。無効・欠落・対応セクションなしも従来表示に戻す。ノート本文・見出し・startは書き換えない。

この基準時刻のある時間枠では、その予定を通常の見積もり候補より優先する。実績・実行中の優先は変えない。同一枠に複数の指定予定がある場合は従来の重なり分数・同点時の元順で比較し、隠れた候補は同じ所属セクションの展開内に残す。見積もり終了が時間枠の途中でも、未完了ならその時間枠の終わりまでは候補を保持し、完了・枠経過で予定代表から外れる。

例：晩ごはんは18時枠に `17:50 …`、促しは21時枠に `20:45 …` と表示する。21:20時点でも未完了の促しは21時枠に残り、20:46–20:52で完了済みならその実績だけになる。start19:00・section18:00なら19時より前へは移さない。早朝のstartは日界を適用してからsectionと比較する。縦幅・矢印の条件・他の候補選択規則は変更しない。

回帰テスト：`tests/reflection-start-section.test.ts`、開始予定の既存タイトル内表示は `tests/reflection-accordion.test.ts`。

#### 未完了項目の表示保証と展開

- 今日の睡眠以前の未着手は、代表か展開内のいずれかに必ず保持する。過去セクション、枠不足、見出し不一致、開始時刻だけで見積もりがない項目も対象。
- 代表でない項目は同じ元セクションの最後の予定帯の展開内に保持する。そこに予定帯がなければ、その元セクションの記録を含む実績帯へ保持する。無関係な未来の帯へ混ぜない。所属できる帯が一つもない場合は時刻なしのまとまりとして保持し、現在や過去の予定時刻を捏造しない。
- 睡眠より下の未着手は時刻指定の有無にかかわらず除外する。SRSの既存除外も保つ。
- 実績開始・終了時刻のある記録は、単独でメモがなくても必ず展開できる。昨日以前にも適用し、展開内で正確な時刻を読めるようにする。代表1件だけで実績時刻・メモ・他項目がいずれもない予定帯のみ、展開要素と矢印を省く。タイトルリンクは保持する。
- 概観表示も展開可能な帯と同じタイトル左位置・右側の予約幅を使う。矢印の有無で本文の位置や省略幅を変えない。

`codex/timeline-live-preview` での仕様。予定は確約された開始時刻ではなく、残り時間で取り組む候補として表示する。元ノートは書き換えない。

1. 既存の1時間枠を使い、完了実績・実行中を最優先する。実行中は開始から現在まで。実績同士は従来の重なり時間・元行順で代表を決める。
2. 今日（日界3時）の時刻未指定・未着手は、元セクションとその1時間枠が少しでも重なれば候補にする。比較に使う分数は見積もりそのものとし、セクションの残り分数では切らない。見積もりなしは0分。時刻指定予定は開始と見積もりから求めた区間が、その1時間枠に重なる分数で比較する。実績のない枠で全セクションの候補を比較し、同点は元行順。
3. 各枠の代表を選んだら、時刻未指定候補の比較用残り見積もりから60分を引く。継続は直前の連続枠で同じ候補が代表だった場合だけ。残り30分以下は継続しない。残り30分超〜45分以下は他候補があれば譲り、45分超は残り見積もりで比較する。元の見積もりは書き換えない。0分の候補も上から一度ずつ補充する。
4. 表示順は各枠の比較結果に従う。展開内の予定候補は元行順を保ち、実績同士は従来の記録時刻順を維持する。選ばれなかった候補の所属先は上記の表示保証に従い、元セクションを保つ。睡眠の既存の深夜帯は区間の重なりで扱い、480分という見積もりで23時台の夜候補を押しのけない。
5. 完了・開始・ノート変更・時間経過で再計算する。完了した候補は実績へ移り、未完了の次候補が繰り上がる。過ぎた予定枠は消し、未完了の候補を残り枠へ選び直す。1分ごとの再計算は既存のスクロール保持付き更新を使う。
6. 睡眠の `summary_role` を持つ項目より下の未着手とSRS範囲は候補にしない。過去の日付にはセクション候補・実行中の現在までの推定を追加しない。
7. 予定帯は破線とし、既存の展開・リンクを使う。startとsectionを分ける表示方針に従い、明示された開始予定だけは元の時刻を題名に残す。推定時刻・見積もり分数の追記や専用操作は加えない。

受領例：14:58時点で15時はテーマ検討、16時はKS記事（iPad記事・dotを展開内へ）、17時はジョギング70分（レッグレイズ・スクワット・夕方の音楽を展開内へ）。17:50開始の晩ごはんは17時台では10分、午後の見積もりなしは0分なので17時代表を取らない。18時は晩ごはん60分、19時はアピタ47分、20時は家族会議30分（皿洗いと20:45の促しを展開内へ）。21時は音楽60分、22時は風呂30分、23時は充電5分。95分の候補に競合があれば1枠、190分は3枠、230分は4枠を基本とする。

以下は実験前の標準仕様。未完了・実行中・時刻なし記録の対象と開始予定の表示は、上記の実験ブランチ仕様を優先する。

- Daily Notesの有効なフォルダ・日付形式で対象ノートを探す。日付の所属は元ノートを正とする。
- 標準では完了したチェック項目（`[x]`）だけを活動として扱う。未完了（`[ ]`）・実行中（`[/]`）は補足を含めて除外する。ノート冒頭の前書き・固定本文を活動や独立メモとして拾わない。チェック項目ではない記録・見出し以降の独立メモは保持し、完了記録は実績時刻なし・0分でも残す。補足本文内のネストしたチェックリストは本文として保持する。
- `<!-- llr:srs start -->` から `end` または `done` までのSRSエリアは、完了済みもメモも含めて除外する。同じノートへのリンクでもエリア外の完了記録は対象。コード例のマーカーは範囲として解釈しない。
- この除外を当面の標準とし、設定画面には項目を追加しない。将来の切り替えは検討可能だが、方式・設定UIは未決。対象判定は表示処理と分けて変更できるようにする。
- TaskParserの実績開始・終了だけを時間軸へ使用し、予定時刻を実績として補わない。
- 日界はLLRの3時。午前0〜2時台は翌朝として並べる。終了が開始より早ければ翌日へ進め、日跨ぎも切り捨てない。
- 1時間ごとに実績の重なりが最大の活動を代表にする。同点は元行順。同じ代表が続けばまとめる。個人カテゴリ、睡眠・外出優先は導入しない。
- 元記録は最も重なるブロックへ一度だけ所属する。同じ活動が離れた時間帯の代表にもなった場合、所属記録のない時間帯は展開のない概観として表示する。時刻なしは解析データに保持するが、専用の見出しと記録枠（`.llr-reflection-untimed`）は表示しない。補足は元タスクの次の行から、次のタスク・見出しまでをインデントの有無によらず保持する。複数段落・URL・箇条書きも落とさず、タスクのない独立した本文もメモとして残す。絵文字からAI由来を推定しない。タイトル・補足はObsidianのMarkdown表示でリンク・別名・箇条書き・チェック項目を読める形にする。チェック項目は読み取り専用とし、振り返りから元ノートを書き換えない。コード中の記法はコードとして残す。

## 連続スクロールと位置

- 古い日から新しい日へ並べ、上端で過去、下端で今日までの新しい日を追加する。追加対象がなければ下端ボタンを隠し、終端メッセージは置かない。初回に全ノート本文を読まない。未来日の既存ノートは現行タイムラインでは対象外であり、明日以降を先に作る使い方への表示対応は未決。
- ノートのない期間は日数を示して省略する。日付ジャンプ先が存在しなければ空の日を表示する。今日へ戻れる。
- 追加・更新は表示中の元行または日付の画面内位置を基準に補正する。展開状態と別タブ復帰時の位置を維持する。実行中への自動追従はしない。
- 長い遡行では表示日数を制限して反対端を取り除く。戻れば再読込できる。表示は最大35日分に制限し、展開内容は開いたブロックのみ描画する。
- 詳細はブロックごとに個別に開閉する。一括操作は、日付・「今日」と同じ行に置くボタン1つで切り替える。Backlinksと同じ上下矢印（move-vertical）を使い、すべて開いていれば「すべて折りたたむ」、一部でも閉じていれば「すべて展開」をツールチップとアクセシブル名で示す。専用の段や「詳細」ラベルは追加しない。操作領域はコンパクトにまとめ、本文やメモの読みやすい余白は保つ。
- 一括操作は表示中の全日と、その後スクロールで続く日にも適用する。個別に開閉した状態は更新・日付追加でも維持し、次の一括操作で揃える。閉じる際は、読んでいた補足の親活動を見失わないよう位置を補正する。
- 各記録には元デイリーノートへの移動アイコンを置かない。本文内のノートリンクはそのまま利用できる。

## 表示設計

スクロール領域に独自の説明ラベルは付けない。

上部はLLRサイドバーと同じ「MM-DD 曜」の日付表示と、その右に「〈 TODAY 〉」を置く。日付を押すと標準HTML日付入力のカレンダーを開き、選択した日のタイムラインへ移動する。ノートのない日も選択でき、ノートは作成しない。独立したカレンダーアイコンは置かない。右端は一括開閉・用紙アイコン・表示切替の順とし、タスク表示では一括操作とその空枠を取り除く。表示を切り替えても日付と移動操作は左、利用可能な操作は右のまとまりを保つ。各記録の移動矢印も表示しない。左右は暦の前後1日へ移動し、無記録の日も飛ばさない。閲覧日付はスクロールへ追従する。今日では右矢印を無効にし、未来日は選択不可。「今日」は常設・有効のままとし、今日の先頭へ戻れる。矢印と文字ボタンの透明な通常状態・ホバーはLLRサイドバーと共有する。日付と他の操作は高さと文字の中心を揃える。狭幅は採用寸法に従って操作幅と日付文字を調整し、本文文字を縮めない。前年以前では年を日付の上に小さく補う。非表示のネイティブ日付入力はレイアウトやTab移動へ重複参加させず、カレンダー操作中の選択値をスクロール追従で上書きしない。

時刻軸と活動の領域を分ける。軸は数字だけの2時間刻み（0・2・4…）とし、活動の開始位置と高さは1時間単位で計算する。ラベルのない13時なども座標は持つ。軸の数字を見出しへ重ねて表示せず、「:00」「翌」「○日後」は加えない。元記録の正確な開始・終了時刻は本文内で読む。

概観は03:00〜翌03:00の日別範囲へ収める。日跨ぎは概観だけ日界で区切り、元記録の全時刻・本文は変更せず一度だけ展開する。範囲の外で始まる記録は「このノートの日界後の記録」に残す。単独の0分・終了未記録も該当する1時間の概観へ含める。これは表示上の所属であり、元記録の実績区間を補わない。先頭末尾の空白時間は省略し、活動間の空白は時間軸の間隔として残す。

閉じた活動は1時間1マスの一定尺度とし、通常ノートの行高とテーマの余白から高さを算出する。デスクトップ最小40px・タッチ最小44pxを確保する。開いた活動の高さは、元の時間帯の高さと「見出し＋本文に必要な高さ」の大きい方とする。元の時間帯へ本文高を加算したり、本文の後ろへ残り時間分の空白を足したりしない。内部の時刻を帯の全高へ均等に配分し、後続活動は増加した高さだけ押し下げる。12〜15時なら13時は全高の1/3、14時は2/3の位置となる。開いている帯だけは読むために局所的な時間尺度が伸びる。個々のメモを実時刻の縦位置に置く方式ではない。

活動の占有範囲は軸の右側だけの薄い無彩色の面で示す。色はテーマのホバー色を薄くしたものを使い、分類色は導入しない。枠・影・追加の内外余白は付けず、開閉で基調色を変えない。括弧・継続罫・活動名の反復・実績の所要時間の重複表示は置かない。元lifelog画面の「軸で時刻、面で占有範囲を読む」構造を参考にし、本文高を最初の1マスの後へ一括で足す展開計算は移植しない。

角丸10px、ホバー色、120msの変化はLLRサイドバーと同じ変数を使う。閉じた活動は全時間帯を一つの操作対象とし、全体のホバー・フォーカスで操作面が強まり、題名リンク以外の面を押すと活動全体が開く。見出し右端に閉状態は右向き、開状態は下向きの矢印を置く。開始見出しはネイティブsummaryでキーボード操作と展開状態を保持する。開いた後は開始見出しの題名リンク以外だけが閉じる操作とホバーの対象で、本文・継続時刻・余白では閉じない。

元記録はタイトル、その下に控えめな開始・終了時刻、続いてメモを置く。開始と終了が同じなら時刻を一度だけ表示する。題名の元データにあるノートリンクは、閉状態・展開状態とも通常の紫色と常時下線で表示し、押すとリンク先へ移動する。リンク操作は開閉に伝播させない。リンクのない題名に架空のリンクを付けず、複数リンクも個別に保つ。同じ代表題名は展開本文へ重複させない。本文内のリンク・別名・Markdownも機能する。本文の文字選択とリンク操作を妨げず、チェック項目は読み取り専用。

背景・文字・ホバーはObsidianテーマの `--background-primary`・`--text-normal`・共有のホバー変数を使い、親ペインの背景色に依存させない。ライト・ダーク双方で配色を確認する。活動名15px・行高1.5、補足12pxにそろえ、フォントはObsidianのテーマ変数を使う。固定操作部は左右20px。時間軸には24pxの数字専用領域と活動面まで8pxの空きを確保し、活動面の左端を32px、題名・展開本文を40pxに置く。数字を活動面・境界線と重ねず、桁全体を専用領域内に収める。タイトルは一行、展開本文は折り返しを維持する。時間の高さは本文行高とテーマ余白から算出し、40px以上、タッチ環境44px以上で活動・空き時間へ同じ尺度を適用する。幅変更時も再描画を待たずに反映する。操作・時刻・日付はテーマのUI変数を使う。本文段落の余白を保ち、メモのない短い記録間の余白は小さくする。閲覧中の日付は固定操作領域に追従表示し、日付入力の操作中を除き同じ日付へ更新する。最終日は短い日でも上端へ移動できる高さを確保する。

### 表示の判断基準

均等な時間軸から、いつ何をしていたかを大まかに把握できることを優先する。既存LLRサイドバーに寄せる対象は配色・文字・余白・ホバー等の見え方であり、時間軸をなくした記録一覧への変更ではない。比較用に追加した一覧は本人に不採用と判断され、切替ごと撤去した。分単位の実績時刻や「○時台」のラベルを概観へ増やして、位置・面積で読める時間情報を文字に置き換えない。細かな情報を確認するためだけの開閉を増やさない。

### 一つのLLR画面での切替

既存の `llr-summary-view` を一つのLLR画面として使い、タスクとタイムラインの描画・操作・対象データは分けて保持する。切替は日付行右端の単一ボタンで、ツールチップとアクセシブル名は「タイムラインを表示」「タスクを表示」。新しいタブ行や操作行は増やさない。タイムライン側にはEstimateを追加しない（採否は未決）。タスク側のEstimateは維持する。

同じ日を往復したときは各表示のスクロールとタイムラインの開閉状態を保ち、切替後は同じ場所の切替ボタンへフォーカスを移す。これは同じ画面を開いている間の状態保持で、再起動後のスクロールや個別展開の永続保存ではない。ワークスペースには表示モードと日付を保存する。表示日を変更してから切り替えた場合は、切替先もその日へ移動する。別日へ移ったタスク表示は先頭から始める。タイムラインの日付移動は初回読込・追加読込・更新と同じキューで直列実行する。ワークスペース復元時にペインが非表示、またはプラグインCSSが未適用なら指定日を保持し、スクロール可能な描画領域になってから位置を合わせる。最終日にも移動できる高さを位置計算前に確保し、前日の位置へ制限されることを防ぐ。読み込みに失敗した切替は直前の表示へ戻し、再試行できるようにする。タスクとタイムラインの上部日付は、選択日の既存デイリーノートと表示日を同時に移動する。欠損日は元の表示を保つ。用紙アイコンでも表示日のノートを開ける。今日ボタンの表示日だけを戻す操作とは区別する。タイムラインの一括操作は展開対象なしでは無効にする。

旧振り返りタブの保存状態は新しいLLR画面へ移行し、同じサイドバー内の重複を一つにまとめる。中央ペインに置いた独立したLLR画面は残す。埋め込んだ描画用ItemViewの空コンテナやネイティブ余白で、本文の幅・高さを二重に消費しない。
