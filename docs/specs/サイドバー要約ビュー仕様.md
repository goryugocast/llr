## 1. 概要
サイドバーのサマリービューを、デイリーノートの内容を俯瞰するための軽量ビューとして提供する。
現状は「閲覧・ジャンプ中心」の実装とし、編集機能は将来拡張とする。

## 2. 現状仕様（Implemented）

### 2.1 ヘッダー
- 日付表示 `MM-DD (曜)`（曜日は日本語、土日色分け）
- 前日 / `TODAY` / 翌日 ナビゲーション
- 日付ラベルクリックで日付を選び、対応するデイリーノートとサイドバーを同日に移動する。用紙アイコンでも表示日のノートを開ける
- 独立した2列の集計（カード背景なし）:
  - `EST. TOTAL`: 「未来」に残っている通常タスクの見積り合計
  - `EST. FINISH`: 「未来」の通常タスクだけで見た終了予定時刻
  - `EST. FINISH` は通常タスクの終了見込み一つだけを表示し、睡眠込みの補足時刻は表示しない。
  - `summary_role: sleep` は `EST. TOTAL` / `EST. FINISH` の通常計算から除外し、内部では睡眠込みの補助時刻を算出するが、ヘッダーには表示しない
  - `summary_role: sleep` より下に元ノートで並んでいた未完タスクは「今日はやらない」扱いとして、サイドバー表示とヘッダー計算の両方から除外する
    - 例外: 実行中（`[/]`）のタスクは、`sleep` より下にあってもサイドバーに表示する。表示位置は `未来` 先頭の実行中グループ（他の実行中タスクと同じ場所、行順）。ただし `EST. TOTAL` / `EST. FINISH` の見積り計算からは引き続き除外し、他タスクの積み上げ時刻もずらさない
  - `summary_role: sleep` が完了済みになった場合、その日の未来タスク表示は全体を閉じる。`sleep` の上下に関係なく、未完タスクはサイドバー未来欄とヘッダー計算から外す
    - 例外: 実行中（`[/]`）のタスクだけはサイドバーに表示する（見積り計算からは除外する）

### 2.2 リスト構造
- サイドバーはロジック上、`過去` と `未来` の2つだけで扱う
- 表示順は `過去` -> `未来`
- 同一行の重複表示を抑制（行番号ベース）
- タスク表示は2段構成
  - 上段: タスク名（`[[wikilink]]` はクリック可能）
  - 下段: `HH:mm - HH:mm` + durationバー。DOMと読み上げ順もこの順序にする
- 実行中タスクは薄いボックス背景で強調
- 完了タスクは打ち消し線を使わず、時刻と本文を少し弱いトーンで表示する
- `過去`: 完了タスクを実績時刻順で並べたもの
- `未来`: 未完タスクを、`進行中 -> 進行中より上にある未完 -> 残り` の順で並べたもの
- `未来` のうち、元ノートで `summary_role: sleep` より下にある未完タスクは表示しない。ただし実行中（`[/]`）のものは先頭の `進行中` グループに入れて表示する（見積り計算には入れない）
- CSS class は見た目のためだけに `完了 / 実行中 / 取り残し見た目` を使ってよいが、並び順・見出し・時刻計算のロジックには使わない

### 2.3 動的時刻積み上げ (Dynamic Time Stacking)
- `過去`: 実績時刻をそのまま表示する
- `過去` の並び順は単純な `HH:mm` 昇順ではなく、日付判定ロジックと同じ日付境界（現状 `03:00`）で正規化する
  - 例: `23:40` の後に `00:30` の完了 `sleep` が来た場合、`00:30` はその日の末尾側として扱う
- `未来`: 現在時刻を起点に、上から順に時刻を積み上げる
- `未来` の先頭に実行中タスクがある場合:
  - 見積あり -> 開始 + 見積の終了予定を表示
  - 見積なし -> 表示上の終了時刻は現在時刻に寄せる
- `未来` の2件目以降は、直前の終了予定から順に積み上げる
- 未来の長さは制限しない。深夜をまたいでも、そのまま翌時刻として積み上げる
- 未着手行に単一時刻（例: `- [ ] 12:00 [[昼ごはん]] (60m)`）がある場合:
  - チェック記号直後の先頭トークンが `HH:mm` または `HHmm` なら、`HH:mm` に正規化して「予約開始時刻」として扱う
  - 例: `- [ ] 1800 ばんごはん 30m` は `18:00` 開始見込みとして扱う
  - 時刻トークンはタスク本文表示から除外する
  - 現時点では並び順や時刻積み上げの拘束には使わない
  - タスク名の直後に tiny の時計 + 時刻を表示する
  - `displayStartTime` が予約開始時刻を超えた場合のみ、時刻欄を段階的に赤くする
  - 着色は 1分超過から開始し、5分刻みで強くなり、60分超過で上限に達する

### 2.4 セクション区切り（Routine Sections 連動）
- `Routine Sections` 設定（時刻 + ラベル）を使って、リスト中に軽い区切り線 + ラベルを差し込む
  - 例: `---------- 午前 ----------` 相当の視認性を狙った表現
- 判定基準は主に `displayStartTime`（表示時刻）
- セクション内に項目がある場合のみ表示（空セクションは出さない）
- `過去` は、実績時刻順の並びを上から見て見出しを付ける
- `未来` は、時刻積み上げ後の並びを上から見て見出しを付ける
- `過去` と `未来` の見出し判定は独立して行う
- 見出しの判定も日付境界（現状03:00）で正規化する。`0000` の見出しを設定した場合は夜の後の深夜タスクに適用する。見出しのない時間帯は最後のセクションへ折り返す（従来のサマリー挙動）

### 2.5 時刻警告（Estimate Warning）
- セクション区切りラベルの着色は検討したが、意味がぶれやすく視認性も不安定になりやすいため採用しない
- 通常タスクに対する一律の時刻着色は、現時点では採用しない
- 設定 `Estimate Warning` が ON のとき、残り見積り時間に基づく予定警告表示を有効にする
- 例外として、予約開始時刻付きタスクだけは超過時に段階着色する
- セクション見出しは無色固定とする

### 2.6 自動スクロール（実行中タスク）
- 目的は「今のタスクを見失いにくくする」ことであり、通常閲覧の手動スクロールを奪いすぎないことを優先する
- 強い自動スクロール（上寄せ）:
  - 新規表示時
  - 前日 / `TODAY` / 翌日 の日付切替時
  - 対象日ファイルが切り替わった直後
  - 実行中タスクがあれば、リスト上端から少し余白を残した位置へ合わせる
  - `TODAY` は現在 `requestAutoScrollToRunning()` を使い、上記の強い自動スクロール条件に含まれる
- 弱い自動スクロール（最小限の補正）:
  - 通常の再描画時は、まず前回のスクロール位置を復元する
  - そのうえで、実行中タスクが見切れている場合だけ、表示領域に入る最小量だけ補正する
  - 実行中タスクがすでに快適に見えている場合は動かさない
  - 実行中タスクが切り替わった場合は、通常再描画でも一度だけ位置補正を許可する
- 手動スクロール尊重:
  - ユーザーがリストを手動スクロールした後は、一定時間（現状 15 秒）弱い自動スクロールを抑止する
  - これにより、内容確認中に勝手に「今」へ引き戻されることを避ける
- 実装上の安定化:
  - スクロール位置計算はリストコンテナ基準の相対座標で行い、ヘッダー領域に潜り込みにくくする
  - 起動直後や再描画競合で強い自動スクロールが上書きされにくいよう、短時間の再適用ウィンドウを持つ
- 実行中タスクがない場合は、通常のスクロール位置復元を優先する
- 将来の拡張候補:
  - 実行中タスクがないとき、`TODAY` 押下時だけ未着手先頭項目へスクロールする案は未実装
  - 現状は「実行中がなければスクロール位置復元を優先」が正式仕様

### 2.7 更新モデル
- `metadataCache.on('changed')` による対象日ファイル変更検知
- 1秒デバウンスで再描画（入力中の過剰更新抑制）
- `DocumentFragment` + `replaceChildren` による一括置換でフリッカー低減
- アクティブノート切替時は対象日を再解決して再描画
- アクティブノートが同じ対象日ファイルのままでも、サイドバーへ戻ったタイミングで軽い再同期を許可する

### 2.8 クリック挙動
- タスク行クリック: 該当 Markdown 行へジャンプ（カーソルは行末）
- タスク名内 `[[wikilink]]`: 対応ノートを開く（行ジャンプより優先）
- 日付ラベルクリック: 日付確定で既存デイリーノートとサイドバーを同日に移動する。欠損日は通知して元の表示を保ち、過去ノートを自動作成しない。今日のノートはCore Daily Notesの既存取得経路を使う
- 用紙アイコン: 表示日のデイリーノートを既存のCore Daily Notes API・探索・通知・開く先で開く。新しい作成処理は追加しない

## 共通表示の採用基準（2026年11月11日）

- 同一ペインでタスク／タイムラインを切り替える。左右並列表示は追加しない。
- 日付、集計、タスクの時間帯見出し・活動名は左右20px。タイムラインは独立した時間軸を確保し、題名・展開本文の左端を40pxとする。活動名15px・行高1.5、時刻／補足12px。Obsidianのフォント・テーマ変数を使う。
- タスクは上下8px、題名と時刻の間4px、1行省略。全行カード化せず、実行中強調と予定時刻の時計を保持する。バーは高さ2px・最大92pxで120分尺度を保つ。
- ヘッダーは左に日付・前日・Today・翌日、右にノート・ビュー切替。タスクに一括開閉の空枠を置かない。
- 日付20px／曜日12px、上下12px・左右20px。操作28×32px（アイコン17px・間隔2px）、移動22／40／22px（間隔2px）、日付と移動6px、左右の群は最低8px。
- ペイン幅320px未満は日付18px／曜日11px、操作22×32px、移動20／34／20px（間隔2px）、群間4px。280pxでも操作を隠さず1行を保つ。
- 集計はラベル11px／値15px、内容に合う列幅と列間16〜28px。両列ともラベル上・値下（間4px）、左揃え。文字1.5倍でも自然に高さを増やす。
- 日付は透明背景でホバー時の文字色とキーボードフォーカスを示す。操作には読み上げ名とツールチップを付ける。
- タスクの今日0時／タイムライン3時、未来日制限、新しいノート作成、日別見出しのノート操作は今回変更しない。
- キーボード・タッチ・日付ピッカー・狭幅は実機検証が必要。静的描画を実機合格とはしない。

### 日付ピッカーの起動方法と実機確認（2026年11月12日）

0.5.1のモバイルでは表示用ラベルの上に実際の日付入力を置き、入力自体を直接タップする。ラベルは表示を維持し、読み上げとフォーカスの対象は日付入力一つにする。別ボタンからfocusとshowPickerを重ねて呼ばない。PCではラベルからネイティブピッカーを開き、APIが未対応・拒否の場合は入力の標準操作へ戻す。両ビューは `src/view/native-date-picker.ts` を共用する。

WebKitには[iOSでshowPickerが動作しない報告](https://bugs.webkit.org/show_bug.cgi?id=261703)がある。関数の存在だけをモバイルでの起動保証にしない。本人の「モバイルで押すと消える」という申告を受けて修正したが、修正前の実機症状は直接採取していない。

修正後のiPhone実機では、タスク・タイムラインともピッカー表示、日付選択、選択せず閉じる操作、再表示、ビュー切替後の操作と日付表示の維持を確認した。PCも通常幅で実ピッカーによる日付選択・キャンセル・再クリック・ビュー往復後の操作を確認。PC狭幅の実操作は座標指定のツールエラーにより未確認で、固定幅fixtureの合格で代用しない。ノート作成や元データの変更は行わない。

2026年11月12日に本人がプラグインをローカル受領し、残るPC狭幅の実操作確認は終了した。未実施の確認を合格扱いにはせず、公開・タグ作成とは分ける。


### モバイルの可読性と右端と末尾余白（0.5.1）

- モバイルの活動名・記録タイトル・集計値は17px以上、時刻・補足・集計ラベル・区切りは13px以上とする。Obsidianの標準UI文字サイズがこれを上回るときは、その設定へ追従する。PCの15px／12px／11px指定は変えない。
- モバイルのタスク題名は最大2行で折り返し、長い英数字も横へはみ出させない。時刻は題名の次の行、バーはその下に配置する。スマホだけバーの最大幅92pxを解除し、本文と同じ幅へ伸ばす。予定時刻は時刻行の右端へ置き、バーの時間尺度120分は維持する。PCの配置は変えない。
- Obsidianのfloating navigationを使うモバイルdrawerでは、標準の48pxフェードが最終行へ重なる。一覧とタイムラインのスクローラに64px（フェード48px＋読後余白16px）の下余白を設ける。中央ペインやPCには適用せず、標準のペイン選択・ノート見出し・フェード自体は変更しない。
- 実iPhoneの画面393×852px、LLRペイン幅約330pxで確認。Obsidianの文字設定16pxと24pxで両表示を確認し、16pxへ戻した。長題名の2行表示と、末尾の時刻・バーをフェードの上で読めることを実画面で確認した。PCの既存描画確認も通過。2026年11月12日に親チャットが修正前後とMac両ビュー各282・322・522pxの実画面を確認して受領。実行中行は当日0件のため、今回のiPhone実画面では未検証。


### モバイルの簡略ヘッダーと日付選択（2026年11月13日のローカル修正）

- 本人指定によりモバイルだけ前日・Today・翌日をヘッダーから外す。日付と直接操作のアイコンを1行に置く。タスクはノートと表示切替、タイムラインは一括開閉・ノート・表示切替を残す。PCは0.5.1のToday・矢印・配置を保つ。
