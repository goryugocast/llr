# Routine Note Frontmatter Specification

`routine/` 直下のルーチンノート（1ノート = 1ルーチンタスク）における YAML Frontmatter のフィールド仕様。

## こんな時に見る
- ルーチンノートにどんなフィールドが書けるか確認したい
- `rollover` / `start_before` / `summary_role` の意味を知りたい
- ルーチンを停止したい（`repeat: none`）

## Status
- **Implemented (core fields)**
- `repeat` の詳細文法・計算ルールは [[ルーチンエンジン仕様]] を正本とする。
- `rollover` 既定値の表もこの文書（§5）を正本とする。

## 1. 目的
- ルーチンタスクの見積り・表示・並び順・次回予定日をノート単位で定義する。
- ノート本文は自由記述、機械処理に必要な値は Frontmatter に集約する。

## 2. Frontmatter Fields (Current)

| Property | Type | Required | Description |
|---|---|---|---|
| `estimate` | number | No | 見積もり時間（分）。展開時に `(30m)` 形式で付与。 |
| `start` | number (`HHmm`) | No | 開始予定時刻。展開時に `09:00 ` を付与。 |
| `start_before` | number \| string | No | `next_due` の何日前から表示するか。`5` / `5 day` / `5 days` / `5日` を受け付ける。 |
| `section` | number \| number[] (`HHmm`) | No | 展開時の時間帯分類・並び順の補助。`Routine Sections` 設定と連動。複数指定するとその数だけ展開する（§6）。 |
| `repeat` | string \| number | No | リピート規則。**主パラメータ**。数値ショートハンドや日本語短縮も可。 |
| `schedule` | string | No | **旧互換**。読み取り対応のみ（新規記述は `repeat` 推奨）。 |
| `frequency` | object | No | **旧旧互換**。読み取り対応のみ。 |
| `next_due` | date (`YYYY-MM-DD`) | System | 次回予定日。完了時に自動更新。未設定なら `repeat` から実効期日を導出する（§3.4）。 |
| `rollover` | boolean | No | 未完了タスクを翌日以降も持ち越して表示し続けるかどうか。`true` / `false`。 |
| `summary_role` | string | No | サイドバー集計の特別扱い。現状は `sleep` を想定。 |
| `sort_order` | number | No | **未実装**。展開時の追加ソートキー案（現行コードは読まない）。 |
| `captures` | object | No | **未実装**。Dispatcher 将来機能向けの予約領域（現行コードは読まない）。 |

## 3. `repeat` の扱い（概要）

### 3.1 基本方針
- 新規記述は `repeat` を使う。
- `repeat` は以下を受け付ける:
  - 数値ショートハンド（例: `1`, `10`）
  - 日本語ショートハンド（例: `毎週月曜`, `隔週月水金`, `毎月末`, `第2土曜日`）
  - 英語詳細構文（例: `every week on mon`, `every 5 days from due`）
- 内部では `every ...` 形式へ正規化して解釈する。

### 3.2 特殊値
- `repeat: none` / `repeat: no` / `repeat: 0`
  - 停止扱い。
  - 完了時に `next_due` を更新せず、既存 `next_due` があれば削除する。
  - `next_due` を手で書いた場合はその日に一度だけ表示する（単発予定の指定）。既定 `rollover: true` により、未完了のまま期日を過ぎるとその後は毎日表示に残る。

### 3.3 未設定時の親切な補完
- `repeat`（および旧 `schedule` / `frequency`）が未設定のノートを完了した場合:
  - `repeat: 1`（毎日）を自動付与
  - `next_due` を翌日に設定

### 3.4 `next_due` が無いときの表示（0.4.0〜）
- `repeat` が書かれているノートは必ずいつか表示される。表示されないのは `repeat: none` / `no` / `0` のときだけ。
- `next_due` が無い場合は `repeat` から実効期日を導出して判定する。
  - `repeat` 未設定・周期のみの規則（`1`, `10`, `5日後` 等） -> 対象日（その日から表示・そこから周期が始まる）
  - 暦に紐づく規則（曜日固定・毎月X日・第N曜日・年次） -> 対象日以降で最初に条件を満たす日
  - `repeat: none` / `no` / `0` -> 表示しない
- 導出結果はノートへ書き戻さない。`next_due` が実際に書かれるのは完了時だけ。
- 0.3.0 以前は `repeat` 明示 + `next_due` 無しのノートを表示対象から外していたため、`repeat: 1` を書いた新規ノートが一度も出てこない状態が起き得た。この分岐は廃止した。

詳細は [[ルーチンエンジン仕様]] §3.x / §3.6 を参照。

## 4. `start_before`（前倒し表示）
- `start_before` は `next_due` の更新規則を変えない。
- 役割は「そのルーチンを何日前から表示し始めるか」のみ。
- サポート値:
  - 数字: `5`
  - 英語: `5 day`, `5 days`
  - 日本語: `5日`
- 数字だけの文字列（例: `"5"`）も受け付ける。
- 未指定時は `0` 日扱いで、`next_due` 当日にだけ表示する。
- `next_due` が将来日なら、表示期間は `next_due - start_before` から `next_due` まで。
- `rollover: true` を明示した場合、`next_due` を過ぎても未完了の間はその回を維持したまま表示し続ける。
- `rollover` 未指定または `false` なら、`next_due` を過ぎた時点で次の期日に catch-up し、その新しい期日を基準に表示期間を判定する。
- タスク本文に未処理 `@done` があり、かつ完了基準日がこの表示期間内にある場合に限って、その回を明示的に閉じて次回へ送る。
- 成功した `@done` は `→done` に正規化し、再処理対象から外す。

## 5. `rollover`（未完了時の再表示ポリシー）
- `rollover` は `next_due` を直接更新しない。
- 「今日のタスク書き出し」で、そのルーチンを表示対象に残すかどうかの判定だけを制御する。
- サポート値:
  - `true`
    - **明示指定した場合**、未完了で `next_due` が過去でも、その回のまま毎日表示対象に残し続ける。
    - 「完了するまで毎日残す」習慣向け。
  - `false`
    - 未完了で `next_due` が過去の場合でも、内部的に「次の妥当な発生日」まで進めて判定する。
    - ゴミ出し、曜日固定、月次固定などの予定向け。
- 未指定時の既定:
  - `repeat: none/no/0` -> `true`
  - 旧オブジェクト形式の `after` / `every` -> `true`
  - `every ... from completion`（`5日後` 等）-> `true`（完了するまで毎日表示、完了日から再計算）
  - `every ... from due`、曜日固定、月次固定、年次固定、旧 `daily/weekly/monthly/nth_day/yearly` -> `false`
  - due 起点で「未完了でも毎日出し続けたい」場合は `rollover: true` を明示する。

## 6. `section` と見出し分類・複数指定

### 6.1 基本
- `section` は時間帯の境界を表す値。`HHmm` 数値（例: `700`, `1245`, `1830`）を基本とし、`7:00`、`7時30分`、`午後7時` のような時刻表記も受け付ける。単一値でも複数値でも指定できる。
- `Insert Routine` およびデイリーノートのマーカー自動挿入では、設定画面の `Routine Sections`（時刻 + ラベル）を用いて分類する。
- 分類ルール（指定された各値に対して個別に適用する）:
  - `section` 未設定 -> `section` 付きルーチンの後ろ（見出しなし）
  - `section` 設定済み -> `section` と境界時刻を03:00基準の時系列へ正規化し、`section >= time` を満たす最大の時刻のラベルへ。00:00〜02:59は夜の後に続く。既存の `section: 2400` は翌日の00:00相当として扱う
  - 境界と同値はその見出しに含む

### 6.2 複数指定（同一ルーチンを複数の見出しに出す）
- `section` に複数の値を指定すると、そのルーチンは値の数だけデイリーノートに複製される。各複製は対応する見出しの下に1行ずつ入り、同じルーチンノートへのリンクを持つ。
- 「朝と夜どちらでもやりたい」のように、ノートを複製せず1本で複数の時間帯に出したいケース向け。
- 受け付ける書き方:
  ```yaml
  section: 700                  # 単一数値（従来通り）
  section: [700, 1900]          # フロー形式の配列
  section:                      # ブロック形式の配列
    - 700
    - 1900
  section: ["700", "1900"]      # 文字列要素も数値化
  section: 700, 1900             # カンマ区切り
  section: 700 1900              # 空白区切り
  section: 700／1900             # スラッシュ区切り
  section: [700, "1900, 2100"]  # 配列と区切り記法の混在
  section: 7:00, 午後7時30分      # 時刻表記も受け付ける
  ```
- 文字列は、ASCII/全角カンマ（`,` / `，`）、読点（`、`）、空白、セミコロン（`;` / `；`）、スラッシュ（`/` / `／`）、縦線（`|` / `｜`）で分割する。区切りの前後の空白は無視する。
- 文字列全体を `[]`・`{}`・`()` で囲んでもよい。配列の中に区切り文字列を混在させてもよい。
- 時刻表記は `7:00` / `7：00`、`7時` / `7時30分`、`午前7時` / `午後7時`、`7am` / `7pm` を受け付け、内部では `HHmm` 数値に変換する。24時台などの24時間表記も受け付ける。
- 要素のうち数値化できないものは無視する。全要素が無効、または空配列 `section: []` の場合は未設定と同じ扱い（`section` 付きルーチンの後ろ・見出しなし）になる。
- 同じ値が重複していたら1つに畳む（`[700, 700]` は `[700]` と同じ）。

### 6.3 完了処理との関係
- `next_due` の更新はルーチンノート単位で1回だけ行われる。複数の見出しに出た行のうち、どれか1つをチェックすればそのルーチン全体が完了扱いになり `next_due` が進む。
- 他の見出しに出ている行は連動してチェックされない（見た目は独立したチェックボックスとして残る）。
- 同日中に複数の行を重ねてチェックしても、`next_due` の再計算は完了日基準のため実害はない（詳細は [[ルーチンエンジン仕様]]）。SRS ノートの `section` 複数指定は現状想定外（SRS はセクション分類とは別経路でバッチ挿入される）。

## 7. `summary_role`（サイドバー表示専用の補助）
- ノートの見積り/ルーチン更新ロジックそのものを変更するものではない。
- 現状実装の用途:
  - `summary_role: sleep`
  - サイドバー `SummaryView` で、睡眠タスクを `EST. TOTAL` / `EST. FINISH` の通常計算から除外し、睡眠込みの時刻を補助表示する。

## 8. 例

### 8.1 通常ルーチン
```yaml
---
estimate: 30
start: 730
section: 700
repeat: 1
next_due: 2026-02-27
---
```

### 8.2 位相維持したい周期（`from due`）
```yaml
---
repeat: every 5 days from due
next_due: 2026-03-01
---
```

### 8.3 予定日の前日から見せたい固定ルーチン
```yaml
---
repeat: every 4 weeks on tue
start_before: 1 day
next_due: 2026-03-03
---
```

### 8.4 予定日だけに出したい固定ルーチン
```yaml
---
repeat: every week on thu
rollover: false
next_due: 2026-02-27
---
```

### 8.5 完了起点ルーチン（`5日後` / `from completion`）
```yaml
---
repeat: 5日後
next_due: 2026-02-27
---
```
デフォルトで rollover=true。未完了なら毎日表示し続け、完了した日から 5 日後を次の `next_due` に設定する。

due 固定にしたい場合（「X 日ごとに必ず来る」スケジュール型）は `rollover: false` を明示する。

### 8.6 朝と夜どちらにも出したいルーチン（`section` 複数指定）
```yaml
---
estimate: 5
section: [700, 1900]
repeat: 1
next_due: 2026-02-27
---
```
「朝」「夜」それぞれの見出しの下に1行ずつ、計2行が出る。

### 8.7 睡眠タスク（サイドバー特別扱い）
```yaml
---
estimate: 480
section: 2400
repeat: 1
summary_role: sleep
next_due: 2026-02-27
---
```

## 9. Legacy Compatibility Notes
- 旧 `schedule` / `frequency` は読み取り互換を維持する。
- ドキュメント上の詳細仕様は `repeat` を正本として記述する。
