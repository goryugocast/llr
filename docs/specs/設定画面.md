# Configuration Specification

**Status: Partially Implemented**

プラグイン設定画面で提供するオプションの仕様。現状実装と将来候補を分けて記載する。

## 1. Implemented Settings (Current)

| Key | Type | Default | Description |
|---|---|---|---|
| `Estimate Warning` | boolean | `true` | 残り見積り時間に基づく予定警告の表示を切り替える。 |

### 既知の欠落: Large Mobile Checkboxes
`mobileLargeCheckboxEnabled`（モバイルでチェックボックスを大きく表示する）は保存値と CSS クラス切り替えが実装済みだが、設定画面にトグルがない。現状は `data.json` を直接編集したときだけ有効になる。トグル UI を足すか設定ごと廃止するかは未決。

## 2.2 Daily Note Folder Fallback (Implemented)

LLR は「コア Daily Notes プラグインに乗っかる」設計で、デイリー判定に使うフォルダ/書式はプラグインの `daily-notes.json`（実体は `instance.options`）から読む。この設定はその**保険**で、`daily-notes.json` がクラウド同期（特に iCloud の「Mac ストレージを最適化」）で初期値に巻き戻り `folder` が空になったケースを救う。

### 解決ルール（`resolveDailyNoteFolder()`）

- プラグインの `folder` が**非空**ならそれを使う（真実の源）。この設定値は**無視**される。
  - したがってユーザーがプラグイン側でフォルダを変更しても LLR は自動追従し、この設定値が陳腐化して衝突することはない。
- プラグインの `folder` が**空**（または空白のみ）のときだけ、この設定値を使う。
- 両方空なら**ボールト直下（ルート）**を意味する。

### 注意 / 既知の割り切り

- 「プラグインの `folder` が空」は「巻き戻りで消えた」と「意図的にルート直下に置いている」を機械的に区別できない。**デイリーをルート直下に置いている利用者はこの欄を空のままにする**こと（埋めると別フォルダを探しに行き誤爆する）。
- format（日付書式）はこの設定の対象外。空欄時は LLR / Obsidian 双方が既定値 `YYYY-MM-DD` にフォールバックするため、保険対象はフォルダのみとした。
- この解決ルールは判定（`getDailyNoteSettings()`）とパス生成（`getDailyNotePathCandidates()`）の両方で**同一の純関数を共有**する。片方だけ変えると判定と生成のフォルダがズレる非対称バグになるため、必ず `resolveDailyNoteFolder()` を経由する。

### UI

- ルーチンフォルダ同様フォルダ候補サジェストを表示する。
- 空入力を許容する（空＝予備なし＝プラグインに完全に従う）。
- 候補選択 / `Enter` / `blur` で確定し、`normalizeDailyNoteFolder()`（前後スラッシュ除去・空は空のまま）で正規化して保存する。

## 2.1 Routine Folder UI (Implemented)

- 入力欄はフォルダ候補サジェストを表示する。
- 候補選択時（タップ/クリック）は、選択した `folder.path` をそのまま保存する。
- `Enter` または `blur` で確定する場合は、入力文字列を次の順で解決して保存する。
  - 完全一致する実在フォルダ
  - 先頭候補（入力文字列で始まる候補のみ）
- 実在フォルダに解決できない中途値は保存しない（現在の設定値へ戻す）。

## 3. Routine Sections UI (Implemented)

### 3.1 Data Model
各項目は以下の2値を持つ。
- `label`: 見出しラベル（`H1`本文）
- `time`: 4桁時刻 `HHmm`

### 3.2 編集UIの挙動
- 既存行は `ラベル -> 時刻` の順で編集する。
- `New Section` 用の未確定入力行を常設する（押した瞬間に行が飛ばないようにする）。
- 追加確定条件（いずれでも可）:
  - `Enter`
  - `blur`（フォーカス外れ）
  - `+` ボタン
- **ラベルと時刻の両方が埋まっている時のみ**追加確定する。
- 読込・保存時に **日付境界（現状03:00）で正規化した時刻順で自動ソート**する。00:00〜02:59は夜の後、03:00〜は次の一日の先頭側へ置く。保存する `HHmm` とラベルの形式は変えない。

### 3.3 Validation / Classification
- 無効な時刻（`HHmm` 以外、または `24:00` 等の不正値）は保存しない。
- 分類ルール（`Insert Routine` / 自動挿入）:
  - ルーチンノートの `section` 未設定 -> `section` 付きルーチンの後ろ（見出しなし）
  - `section` と境界時刻を同じ03:00基準の時系列へ正規化し、`section >= time` を満たす **最大の時刻** のラベルへ入る
  - 境界時刻と同値はその見出しに含む
